### 最终契约（以后端实现为准）

- 响应体 `{code, message, data, timestamp}`，**成功码 200（不是 0）**
- HTTP 状态码 = 业务码高位归类：40000/40100/40300/40400/40900/50000
- 方法：改密 `POST /api/auth/password`；重置密码 `POST /api/admin/users/{id}/password/reset`；
  启禁用 `PUT /api/admin/users/{id}/status?enabled=true|false`（query 参数）
- 角色字符串枚举 `STUDENT/TEACHER/ADMIN`，表 `sys_user.role VARCHAR(16)`
- 手机号输出一律脱敏 `138****0001`
- 初始密码来自配置 `app.auth.initial-password=Init@1234`；显式指定密码才走完整强度策略
- 弱口令黑名单必须含 `Init@1234`、`12345678`

### 联调中修复的真实缺陷

1. **登录失败锁定失效**：`AuthService#login` 上 `@Transactional(rollbackFor = Exception.class)`
   把「密码错误」异常抛出时一并回滚了 `onLoginFail` 的失败计数 → 改为
   `noRollbackFor = BizException.class`。这个坑很隐蔽：单测不易发现，必须连打 5 次才会暴露。
2. **JDBC 连接失败** `Unsupported character encoding 'utf8mb4'`：`characterEncoding`
   要填 **Java** 字符集名 `UTF-8`，不是 MySQL 字符集名。
3. **登录失败文案不符契约**：追加的「还可尝试 N 次」导致断言失败 → 改为逐字一致。
