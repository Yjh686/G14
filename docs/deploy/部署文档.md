# 部署文档（D-09）

> 目标：按本文从零启动整套系统。两条路径——**Docker 一键启动**（推荐演示用）与**本机手动启动**（开发调试用）。
> 所有命令均在仓库根目录 `D:\G14(1)`（Linux/macOS 下为仓库根）执行。

## 1. Docker 一键启动（推荐）

### 1.1 前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Docker Engine | ≥ 20.10，且 daemon 已启动 | `docker info` |
| Docker Compose | v2 插件（`docker compose`，非 `docker-compose`） | `docker compose version` |
| 空闲端口 | 3306（MySQL）、8080（后端直连）、80（前端） | `netstat -ano \| findstr ":80 "` |
| 磁盘 | ≥ 2 GB（镜像 + 数据卷 + 构建缓存） | — |

> **Windows 注意**：Docker Desktop 必须正在运行。若 `docker info` 报
> `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`，说明 daemon 没起来，先启动 Docker Desktop 并等托盘图标变绿。

### 1.2 启动

```bash
cd deploy
docker compose up -d --build
```

首次构建约 5~10 分钟（要拉 maven / node / nginx / mysql 基础镜像并编译前后端）。之后改代码只需 `docker compose up -d --build backend` 或 `frontend` 单独重建。

启动顺序由 compose 的 `depends_on: condition: service_healthy` 保证：MySQL 先通过 `mysqladmin ping` 健康检查，后端才启动。

### 1.3 验证

```bash
docker compose ps                          # 三个服务都应为 running / healthy
curl http://localhost:8080/api/health      # {"code":200,...,"status":"UP"}
curl -I http://localhost/                  # HTTP/1.1 200 OK
curl http://localhost/api/health           # 走 nginx 反代，同样 200
curl -s http://localhost:8080/v3/api-docs | head -c 120   # springdoc 生效
```

浏览器打开 <http://localhost>，用演示账号登录：

| 账号 | 密码 | 角色 | 权限数 |
|---|---|---|---|
| `admin` | `Admin@123` | 系统管理员 | 50 |
| `teacher` | `Teacher@123` | 教师 | 23 |
| `student` | `Student@123` | 学生 | 10 |

> 这三个账号由 `deploy/sql/01_schema_auth.sql` 在 MySQL 首次初始化时写入。**生产部署请立即改密或删除。**

### 1.4 端口与数据

| 服务 | 容器内 | 宿主机 | 说明 |
|---|---|---|---|
| frontend (nginx) | 80 | `${HTTP_PORT:-80}` | 可用 `HTTP_PORT=8000 docker compose up` 改端口 |
| backend | 8080 | `127.0.0.1:8080` | **只绑本机**，仅用于调试直连；正常访问走 nginx |
| mysql | 3306 | `127.0.0.1:3306` | **只绑本机**，避免数据库暴露到局域网 |

数据卷（`docker compose down` 不会删，`down -v` 才会）：

| 卷 | 内容 |
|---|---|
| `mysql-data` | 数据库全部数据 |
| `backend-logs` | `app.log`（滚动 20MB × 7 天） |

### 1.5 常用运维命令

```bash
docker compose logs -f backend        # 看后端日志
docker compose logs -f frontend       # 看 nginx access log
docker compose restart backend        # 重启后端
docker compose down                   # 停止（保留数据）
docker compose down -v                # 停止并删数据（重新初始化会重跑建表脚本）
```

备份与恢复：

```bash
# 备份
docker compose exec mysql mysqldump -uroot -p123456 --databases "G14(1)" > backup.sql

# 恢复
docker compose exec -T mysql mysql -uroot -p123456 < backup.sql
```

### 1.6 关键配置项（环境变量）

`docker-compose.yml` 里通过环境变量覆盖 Spring 配置，不修改镜像内文件：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | `123456` | **生产必须改** |
| `SPRING_DATASOURCE_URL` | `jdbc:mysql://mysql:3306/G14%281%29?...` | 库名 `G14(1)` 的括号必须 URL 编码成 `%28` `%29` |
| `APP_JWT_SECRET` | `campus-survey-G14-1-jwt-secret-key-2025-do-not-share` | **生产必须改**，≥ 32 字节，改了所有旧 token 立即失效 |
| `APP_SECURITY_DEFAULT_PASSWORD` | `G14@init2025` | 新建/重置用户的默认密码（也可在「系统配置」页改） |
| `LOGGING_FILE_NAME` | `/app/logs/app.log` | 容器内日志路径 |
| `HTTP_PORT` | `80` | 前端对外端口 |

修改方式：在 `deploy/` 下建 `.env` 文件，写 `MYSQL_ROOT_PASSWORD=xxx` 等，`docker compose` 会自动读取。

### 1.7 首次初始化发生了什么

MySQL 官方镜像在数据目录为空时，会按文件名顺序执行 `/docker-entrypoint-initdb.d/` 下的 `.sql`。本编排挂载了 01~05 五个脚本：

1. 建库 `G14(1)`（`utf8mb4`）；
2. 建 17 张表 + 索引 + 注释；
3. 写入 3 个角色、50 条权限码、83 条角色-权限关联；
4. 写入 10 项系统配置（站点信息 + 密码策略）；
5. 写入 3 个演示账号。

**`90_cleanup_test_data.sql` 刻意没有挂载**——它是清理脚本，会把业务数据全删，只在开发时手工执行。

> 数据目录非空时初始化脚本不会重跑。要重新初始化：`docker compose down -v` 后再 `up`。

## 2. 本机手动启动（开发调试）

### 2.1 前置条件

| 项 | 本项目实测版本 | 检查 |
|---|---|---|
| JDK | 17.0.20.1（`D:\huanjing\jdk-17`） | `java -version` |
| Maven | 3.9.16（`D:\Maven\apache-maven-3.9.16`） | `mvn -v` |
| MySQL | 8.0.46，root 密码 `123456` | `mysql -uroot -p123456 -e "select version()"` |
| Node.js | ≥ 20（实测 24.16.0） | `node -v` |
| npm | ≥ 10（实测 11.13） | `npm -v` |

### 2.2 建库建表

```powershell
$mysql = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"
$db    = "g14(1)"

foreach ($f in 01_schema_auth, 02_schema_survey, 03_schema_answer, 04_schema_template, 05_schema_config) {
    & $mysql -u root -p123456 --default-character-set=utf8mb4 $db -e "source D:/G14(1)/deploy/sql/$f.sql"
}

& $mysql -u root -p123456 --default-character-set=utf8mb4 $db -e "SHOW TABLES"
```

两个坑：

- `-e "source ..."` 后面**必须再跟库名参数**，否则报 `ERROR 1046 (3D000) No database selected`。
- mysql CLI 会因「在命令行传密码不安全」打一条警告并返回 **exit code 1**，这不是执行失败。

### 2.3 启动后端

```powershell
$env:JAVA_HOME='D:\huanjing\jdk-17'

# 首次需要生成 classpath 文件（改 pom 后必须重新生成）
& "D:\Maven\apache-maven-3.9.16\bin\mvn.cmd" -q -o -f backend\pom.xml -DskipTests compile
& "D:\Maven\apache-maven-3.9.16\bin\mvn.cmd" -q -f backend\pom.xml dependency:build-classpath -Dmdep.outputFile=D:\G14(1)\backend\target\cp.txt

$cp = (Get-Content backend\target\cp.txt -Raw).Trim() + ';' + (Resolve-Path backend\target\classes)
Start-Process "$env:JAVA_HOME\bin\java.exe" -ArgumentList @('-cp',$cp,'com.yjh.backend1.Backend1Application') `
  -RedirectStandardOutput backend\target\run.log -RedirectStandardError backend\target\run.err.log -WindowStyle Hidden
Start-Sleep 14
Invoke-WebRequest http://localhost:8080/api/health -UseBasicParsing | Select-Object -ExpandProperty Content
```

也可以用打包好的 jar（更快，跳过 classpath 拼接）：

```powershell
& "D:\Maven\apache-maven-3.9.16\bin\mvn.cmd" -q -o -f backend\pom.xml -DskipTests package
Start-Process "$env:JAVA_HOME\bin\java.exe" -ArgumentList @('-jar','backend\target\backend1-0.0.1-SNAPSHOT.jar') `
  -RedirectStandardOutput backend\target\jar.log -RedirectStandardError backend\target\jar.err.log -WindowStyle Hidden
```

> **`-Dmdep.outputFile` 必须写绝对路径**。写相对路径时 Maven 以 pom 所在目录为基准解析，产物会落到 `backend\backend\target\cp.txt`，而启动命令读的是 `backend\target\cp.txt`（旧文件），表现为启动时报 `NoClassDefFoundError: com/alibaba/excel/ExcelWriter` 这类「依赖明明加了却找不到」的怪错。

端口被占用时：

```powershell
# 停掉本项目后端
$jp = (Get-CimInstance Win32_Process -Filter "Name='java.exe'" | Where-Object { $_.CommandLine -like '*Backend1Application*' -or $_.CommandLine -like '*backend1-*.jar*' }).ProcessId
Stop-Process -Id $jp -Force
```

### 2.4 启动前端

```powershell
cd frontend\G14
npm install            # 首次
npm run dev            # http://localhost:5173
```

Vite 的 `server.proxy` 把 `/api` 转发到 `http://localhost:8080`，前端代码里 baseURL 始终是 `/api`，开发与生产同源，不需要 CORS 配置切换。

生产构建：

```powershell
npm run build          # 产物在 frontend/G14/dist/
npm run preview        # 本地预览构建产物
```

## 3. 生产部署注意事项

课本项目也需要一份「上线前该检查什么」的清单。

| 项 | 必须做 | 原因 |
|---|---|---|
| `APP_JWT_SECRET` | 换成随机 32+ 字节 | 默认值写在仓库里，任何人都能伪造 token |
| `MYSQL_ROOT_PASSWORD` | 换强密码 | 默认 `123456` |
| 演示账号 | 改密或删除 | `admin/Admin@123` 是公开信息 |
| 默认密码 `G14@init2025` | 在「系统配置」页改 | 所有未改密账号共用同一把钥匙 |
| MySQL 端口 | 不要映射到 `0.0.0.0` | 编排里已绑 `127.0.0.1`，云服务器上仍应确认安全组未放开 3306 |
| 后端端口 | 同上 | 编排里已绑 `127.0.0.1`，对外只暴露 nginx 的 80/443 |
| HTTPS | 在 nginx 上加 443 + 证书 | 否则密码与 token 明文传输；本项目未内置证书 |
| MySQL 持久性参数 | 保持 `innodb_flush_log_at_trx_commit=1`、`sync_binlog=1` | 编排里显式设成这两个值。改成 2/0 能把压测吞吐提高 15 倍，但崩溃可能丢最近 1 秒事务——**这是拿持久性换性能，不能为了跑分偷偷改** |
| `deleted` 数据 | 定期归档 | 逻辑删除的数据永久保留，`sys_operation_log` / `sys_login_log` 会持续增长（日志无 `deleted`，只增不改） |
| 日志轮转 | 确认 `logging.logback.rollingpolicy` 生效 | 已配 20MB × 7 天；容器里落到 `backend-logs` 卷 |

## 4. nginx 配置要点

`deploy/nginx/default.conf` 一个 server 同时托管静态产物与反代 `/api/`，前后端同源——这是不做 CORS 配置的前提。

| 配置 | 值 | 为什么 |
|---|---|---|
| `upstream ... keepalive 32` | 保持后端长连接 | 不开 keepalive 时高并发会堆积大量 TIME_WAIT |
| `proxy_set_header X-Forwarded-For` | `$proxy_add_x_forwarded_for` | 后端 `RequestUtil` 优先取 XFF；不传则登录日志里全员是 `172.x` 容器地址 |
| `proxy_http_version 1.1` + `Connection ""` | — | 与 keepalive 配套，缺一不可 |
| `proxy_read_timeout 300s` | — | Excel 导出是流式响应，默认 60s 对大数据量不够 |
| `location /assets/` `expires 1y` + `immutable` | — | Vite 产物文件名带内容哈希，可以永久缓存 |
| `location = /index.html` `no-store` | — | 否则用户拿到旧入口，指向已被删除的 chunk，白屏 |
| `try_files $uri $uri/ /index.html` | — | Vue Router 用 history 模式，刷新子路由不能 404 |
| `location = /healthz` | `return 200 "ok\n"` + `access_log off` | 给负载均衡/监控探活用，不写日志 |
| `log_format main` 含 `$status` | — | **长期运行故障率的第二份证据来源**：`grep ' 5[0-9][0-9] ' access.log \| wc -l` ÷ 总行数。不能关日志 |

统计故障率：

```bash
total=$(wc -l < access.log)
errors=$(grep -c ' 5[0-9][0-9] ' access.log)
echo "故障率 = $errors / $total"
```

## 6. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker info` 报 `cannot find the file specified` | Docker Desktop 未启动 | 启动 Docker Desktop，等托盘变绿 |
| 后端启动报 `NoClassDefFoundError: com/alibaba/excel/ExcelWriter` | `cp.txt` 是旧的 / 落到了 `backend\backend\target\` | 用**绝对路径**重新执行 `dependency:build-classpath`，确认 `(Get-Content backend\target\cp.txt -Raw) -match 'easyexcel'` 为 True |
| 启动报 `Illegal overloaded getter method ... ReflectionException` | 实体里手写了 `isXxx()` 与 Lombok getter 冲突 | 改名（如 `anonymousEnabled()` / `builtinOnce()` 风格） |
| 数据库连不上，日志 `Access denied` | 密码/库名不对 | 库名含括号：`G14(1)`，JDBC 里要写 `G14%281%29` |
| `ERROR 1046 No database selected` | 执行 `source` 时没跟库名 | `mysql ... "g14(1)" -e "source ..."` |
| 前端页面 200 但接口全 404 | nginx 没反代 `/api` 或 upstream 名字不匹配 | 检查 `default.conf` 的 `location /api/` 与 `upstream campus_backend` |
| 刷新子路由 404 | 缺 `try_files ... /index.html` | 补上 |
| 登录日志里 IP 全是 `172.x` | 没传 `X-Forwarded-For` | 在 `location /api/` 里补 `proxy_set_header` |
| Excel 打开乱码 | `Content-Disposition` 没写 `filename*=UTF-8''` | 后端 `prepareResponse` 已处理，检查是否被改回 `filename=` |
| 学生进不了填写页（403） | 前端用了 `/surveys/{id}`，该路径需要 update/preview 权限 | 大厅跳转必须用 `shareCode` → `/fill/{code}` |
