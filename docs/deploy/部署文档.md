## 0. 先读这一段：凭据不在仓库里

这是公开仓库，所以**代码里没有任何默认数据库密码或 JWT 密钥**。两个凭据必须显式提供，缺失时后端会启动失败并指明缺哪一项——这是刻意设计，不是配置漏了。

| 凭据 | 用途 | 缺了会怎样 |
|---|---|---|
| `DB_PASSWORD` | 连 MySQL | `Could not resolve placeholder 'DB_PASSWORD'` |
| `APP_JWT_SECRET` | 签 JWT，**至少 32 字节** | 同上；不足 32 字节则报 `app.jwt.secret 长度不足 32 字节，HS256 不安全` |

生成一个够强的密钥：

```bash
openssl rand -base64 48          # Linux / macOS / Git Bash
```

```powershell
# Windows PowerShell，没有 openssl 时
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Max 256 }))
```

> 为什么不用默认值：默认密钥写在开源仓库里，等于所有部署共用一把钥匙。任何人拿它就能自己签一个 `ver` 正确的 token 冒充管理员，且改密也踢不掉——因为攻击者可以直接签新 token。启动失败比「悄悄用默认值」安全得多。

## 1. 云服务器上线（路线 A）

### 1.1 买什么配置

按本项目实测占用倒推。实测数据（本机，Linux 容器）：

| 组件 | 常驻内存 | 镜像体积 |
|---|---|---|
| backend（JVM，`-XX:MaxRAMPercentage=75`） | 274 MiB | 482 MB |
| mysql 8.0 | 374 MiB | 1.1 GB |
| frontend（nginx 静态） | 16 MiB | 77 MB |
| **合计** | **约 0.7 GB** | **约 1.7 GB** |

**推荐配置：2 核 2 GB 内存，40 GB 云盘，Ubuntu 22.04 LTS。**

理由与取舍：

- **2 GB 是底线，不是宽裕值。** 三个容器常驻约 0.7 GB，但 MySQL 会随数据量涨 buffer pool，JVM 也要留堆余量。1 GB 机器能起但 OOM 风险高（尤其首次 `docker compose build` 时 maven 编译吃满内存）。
- **必须 2 核。** 首次构建要跑 Maven + npm 两个编译，单核会非常慢（本项目后端 `dependency:go-offline` 就要 68 秒，编译还要更久）。
- **40 GB 盘**：镜像 1.7 GB + 构建缓存约 1 GB + 数据库。按 1000 份答卷 ≈ 1.5 MB 估算，40 GB 能存几万份还有大量余量。
- **不需要 GPU、不需要高 IOPS 盘、不需要独享带宽**。1~3 Mbps 固定带宽足够（这是表单系统，不是视频站）。
- **系统选 Ubuntu 22.04 LTS**，不要选 CentOS 7（已 EOL，docker 源和镜像都麻烦）。

省钱提示：阿里云/腾讯云的**轻量应用服务器**（2 核 2G，学生机常有优惠）比 ECS/CVM 便宜很多，对这个项目完全够用。买的时候注意选「Ubuntu 22.04」，不要选「宝塔面板镜像」（会预装一堆东西，和本文的 Docker 方案冲突）。

**国内服务器必须备案才能用 80 端口对外提供 Web 服务。** 阿里云/腾讯云的大陆机房都要求 ICP 备案，未备案访问 80/443 会被拦截。如果只是想答辩演示、不打算长期挂，有两个选择：

1. 用**非 80 端口**（如 8080）访问——未备案时通常可以用非标准端口，但部分厂商也会拦，实测为准；
2. 买**香港/海外轻量服务器**——不需要备案，代价是大陆访问延迟高一些（本项目页面很小，实际体验差别不大）。

### 1.2 装 Docker


**给 Docker 配镜像加速（国内服务器必做）**，否则拉 `mysql:8.0` 这种大镜像会卡住：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1panel.live",
    "https://dockerproxy.net",
    "https://docker.m.daocloud.io"

sudo systemctl restart docker
```

> 这三个地址是 2026-11 实测可用的。镜像加速器失效很常见，若报 `failed to resolve source metadata ... EOF`，换一个即可（搜「docker 镜像加速 可用」找当期列表）。

### 1.7 开放安全组 / 防火墙

云服务器默认只开 22 端口。**必须手动放行 80**：

- **阿里云**：控制台 → 实例 → 安全组 → 配置规则 → 入方向 → 添加，端口范围 `80/80`，授权对象 `0.0.0.0/0`
- **腾讯云**：控制台 → 防火墙 → 添加规则，应用类型「HTTP (80)」，来源 `0.0.0.0/0`

**不要放行 3306 和 8080**。编排里这两个端口已绑 `127.0.0.1`，即使安全组放开也访问不到，但少开一个口子总归更安全。

如果服务器上还开了 ufw：

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp   # 以后上 HTTPS 用
sudo ufw status
```

### 1.8 用 IP 访问的已知限制

没有域名时能正常跑，但有三件事做不了：

| 限制 | 影响 | 缓解 |
|---|---|---|
| 不能上 HTTPS | 密码和 token 明文传输，公共 WiFi 下可被嗅探 | 答辩/内网演示可接受；真实使用前一定要上域名 + 证书 |
| 换 IP 就换地址 | 云服务器可换弹性 IP，但普通 IP 释放后可能被回收 | 尽量别重建实例 |
| 部分浏览器对纯 IP 限制 | Cookie/剪贴板/地理位置等 API 受限 | 本项目 token 存 localStorage，不依赖 Cookie，实测正常 |

### 1.9 以后买域名了怎么加 HTTPS

不改动任何容器配置，只在宿主机加一层 nginx 反代：

1. 域名解析：加一条 A 记录指向服务器公网 IP，等生效（`ping 你的域名` 能通）。
2. **大陆机房先备案**，备案通过前 80/443 会被拦。
3. 把容器的 80 端口让给宿主机 nginx：

```bash
# deploy/.env 里改
FRONTEND_PUBLISH=127.0.0.1:8080:80
```

```bash
cd deploy && docker compose up -d
```

4. 宿主机装 nginx 与 certbot：

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

5. 新建 `/etc/nginx/sites-available/g14`：

```nginx
server {
    listen 80;
    server_name 你的域名;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 10m;
    }
}
```

6. 启用并签发证书：

```bash
sudo ln -s /etc/nginx/sites-available/g14 /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d 你的域名    # 自动改配置 + 自动续期
```

> `X-Forwarded-For` 必须传。后端 `RequestUtil` 优先取这个头，不传的话宿主机 nginx 这一层会把真实客户端 IP 丢掉，登录日志里全员变成 `127.0.0.1`。
>
> 宿主机 nginx 和容器内 nginx 是**串联**关系：外层管 TLS 和域名，内层管静态资源与 `/api` 反代。不要试图把证书塞进容器，那样续期很麻烦。

## 2. 本机 Docker 一键启动（路线 B）

适合演示与验收，与路线 A 的差别只是不需要安全组和备案。

### 2.1 前置条件

| 项 | 要求 | 检查 |
|---|---|---|
| Docker Engine | ≥ 20.10，daemon 已启动 | `docker info` |
| Docker Compose | v2 插件（`docker compose`，注意没有连字符） | `docker compose version` |
| 空闲端口 | 80 / 8080 / 3306 | `netstat -ano \| findstr ":80 "` |
| 磁盘 | ≥ 3 GB（镜像 + 构建缓存 + 数据卷） | — |

> Windows 上如果 `docker info` 报 `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`，是 Docker Desktop 没启动。注意它不一定装在 `C:\Program Files\Docker\Docker\`，常见位置是 `C:\Users\<用户>\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe`。

### 2.2 端口冲突

开发机上 3306 常被本机 MySQL 占着，8080 常被开发中的后端占着。用 `.env` 绕开，不要改 `docker-compose.yml`：

```bash
MYSQL_PUBLISH=127.0.0.1:13306:3306
BACKEND_PUBLISH=127.0.0.1:18080:8080
```

### 2.3 启动与验证

```bash
cd deploy
cp .env.example .env      # 首次，然后改 MYSQL_ROOT_PASSWORD 和 APP_JWT_SECRET
docker compose up -d --build
docker compose ps
docker compose logs -f backend    # 看启动日志，Ctrl+C 退出
```

### 2.4 数据卷

| 卷 | 内容 | 说明 |
|---|---|---|
| `mysql-data` | 数据库全部数据 | `docker compose down` 保留，`down -v` 删除 |
| `backend-logs` | `app.log`（20MB × 7 天滚动） | 同上 |

> 初始化脚本只在数据目录为空时执行。想重新初始化（比如演示前清空数据）：`docker compose down -v && docker compose up -d`。

## 3. 本机手动启动（路线 C，开发调试）

不用 Docker，直接跑 java 与 vite，改代码即时生效。

### 3.1 前置条件

| 项 | 本项目实测版本 |
|---|---|
| JDK | 17（`D:\huanjing\jdk-17`） |
| Maven | 3.9.16（`D:\Maven\apache-maven-3.9.16`） |
| MySQL | 8.0.46 |
| Node.js | ≥ 20（实测 24.16.0） |
| npm | ≥ 10（实测 11.13） |

### 3.2 建库建表

```powershell
$mysql = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"
$db    = "g14(1)"

foreach ($f in 01_schema_auth, 02_schema_survey, 03_schema_answer, 04_schema_template, 05_schema_config) {
    & $mysql -u root -p --default-character-set=utf8mb4 $db -e "source D:/G14(1)/deploy/sql/$f.sql"
}

& $mysql -u root -p --default-character-set=utf8mb4 $db -e "SHOW TABLES"
```

两个坑：

- `-e "source ..."` 后面**必须再跟库名参数**，否则报 `ERROR 1046 (3D000) No database selected`。
- mysql CLI 会因「在命令行传密码不安全」打一条警告并返回 **exit code 1**，这不是执行失败。

### 3.3 启动后端

```powershell
cd backend
copy .env.local.example .env.local    # 首次，填 DB_PASSWORD 与 APP_JWT_SECRET
.\start-local.ps1                     # 编译 + 启动
```

`start-local.ps1` 做的事：读 `.env.local` → 注入环境变量 → 停掉本项目的旧 java 进程 → `mvn compile` → 后台启动 → 轮询 `/api/health` 直到就绪。参数：`-Port 8081`、`-Jar`（改用打包的 jar）、`-SkipBuild`（跳过编译）。

不想用脚本就手动注入：

```powershell
$env:DB_PASSWORD   = "你的数据库密码"
$env:APP_JWT_SECRET = "至少32字节的随机串"
$env:JAVA_HOME = "D:\huanjing\jdk-17"

& "D:\Maven\apache-maven-3.9.16\bin\mvn.cmd" -q -o -f backend\pom.xml -DskipTests package
& "$env:JAVA_HOME\bin\java.exe" -jar backend\target\backend1-0.0.1-SNAPSHOT.jar
```

> **`-Dmdep.outputFile` 必须写绝对路径**（用 `-cp` 方式启动时需要 cp.txt）。写相对路径时 Maven 以 pom 所在目录为基准，产物会落到 `backend\backend\target\cp.txt`，而启动命令读的是 `backend\target\cp.txt`（旧文件），表现为 `NoClassDefFoundError: com/alibaba/excel/ExcelWriter` 这类「依赖明明加了却找不到」的怪错。

### 3.4 启动前端

```powershell
cd frontend\G14
npm install            # 首次
npm run dev            # http://localhost:5173
```

Vite 的 `server.proxy` 把 `/api` 转发到 `http://localhost:8080`，所以前端 baseURL 始终是 `/api`，开发与生产同源，不需要切换 CORS 配置。

生产构建：`npm run build`（产物在 `frontend/G14/dist/`）、`npm run preview`（本地预览）。

### 3.5 访问入口

| 入口 | 地址 |
|---|---|
| 前端 | <http://localhost:5173> |

## 4. 环境变量全表

容器部署读 `deploy/.env`；本机开发读 `backend/.env.local`（键名相同，但后者只需 `DB_PASSWORD` 与 `APP_JWT_SECRET`）。

### 4.1 必填（没有默认值，缺了就起不来）

| 变量 | 说明 |
|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码。**首次初始化后改它不会改库里已有密码**，要变必须 `down -v` 重建 |
| `APP_JWT_SECRET` | JWT 签名密钥，≥ 32 字节。换了它所有已签发令牌立即失效（这是强制全体重新登录的手段） |

### 4.2 可选（都有合理默认值）

| 变量 | 默认 | 说明 |
|---|---|---|
| `FRONTEND_PUBLISH` | `80:80` | 前端对外端口。套宿主机 HTTPS 反代时改 `127.0.0.1:8080:80` |
| `BACKEND_PUBLISH` | `127.0.0.1:8080:8080` | 后端端口，只绑回环。供运维 curl 排障，公网不需要 |
| `MYSQL_PUBLISH` | `127.0.0.1:3306:3306` | MySQL 端口，只绑回环。开发机 3306 被占时改 `127.0.0.1:13306:3306` |
| `BACKEND_MEM` | `1g` | 后端容器内存上限。**必须设**：`MaxRAMPercentage` 不设上限时按宿主机内存算，2G 机器上会被 OOM Killer 杀掉且日志里查不到原因 |
| `JAVA_OPTS` | `-XX:MaxRAMPercentage=75 -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai` | JVM 参数 |

### 4.3 容器内部（不需要你改）

| 变量 | 值 | 说明 |
|---|---|---|
| `SPRING_DATASOURCE_URL` | `jdbc:mysql://mysql:3306/G14%281%29?...` | 库名 `G14(1)` 的括号必须 URL 编码成 `%28` `%29` |
| `DB_PASSWORD` | 取自 `MYSQL_ROOT_PASSWORD` | 与 `application.yml` 里 `${DB_PASSWORD}` 对上，排障时不用猜覆盖了什么 |
| `LOGGING_FILE_NAME` | `/app/logs/app.log` | 落在 `backend-logs` 卷 |

### 4.4 不在环境变量里的两项

| 项 | 真实来源 | 怎么改 |
|---|---|---|
| 新建/重置用户的**初始密码** | `sys_config` 表的 `security.default-password` | 登录后「系统配置」页改，立即生效 |
| **密码强度规则**（长度/字母/数字/特殊字符） | `sys_config` 表的 `security.password.*` | 同上 |

`application.yml` 里**刻意没有**这两项的配置——放一份就会出现「yml 说 A、页面显示 B」的两套真相，改完还不生效。

## 5. 首次初始化发生了什么

MySQL 官方镜像在数据目录为空时，按文件名顺序执行 `/docker-entrypoint-initdb.d/` 下的 `.sql`。本编排挂载 01~05 五个脚本：

1. 建库 `G14(1)`（`utf8mb4`）；
2. 建 17 张表 + 索引 + 中文注释；
3. 写入 3 个角色、50 条权限码、83 条角色-权限关联；
4. 写入 10 项系统配置（站点信息 4 项 + 密码策略 6 项）；
5. 写入 3 个演示账号与 2 份演示问卷。

**`90_cleanup_test_data.sql` 刻意没有挂载**——它是清测试数据的，会把业务数据全删，只在开发时手工执行。

> 关于中文乱码：MySQL 官方 entrypoint 调 `mysql` 客户端时**不带** `--default-character-set`，而容器默认没有 `LANG`，客户端会退回 `latin1`，把 UTF-8 建表脚本里的中文写成双重编码（「校园问卷系统」→「æ ¡å›­é—®å·ç³»ç»Ÿ」）。本编排用两道保险解决：`LANG: C.UTF-8` 环境变量 + `deploy/mysql/client-charset.cnf` 钉死客户端字符集。两者任一生效即可。

## 6. 生产部署检查清单

| 项 | 必须做 | 原因 |
|---|---|---|
| `APP_JWT_SECRET` | 换成随机 32+ 字节 | 仓库里没有默认值了，但仍要确保不是随手敲的弱串 |
| `MYSQL_ROOT_PASSWORD` | 强密码 | 同上 |
| 演示账号 | 改密或删除 | `admin/Admin@123` 是公开信息，任何人都知道 |
| 初始密码 `security.default-password` | 「系统配置」页改 | 所有未改密账号共用同一把钥匙 |
| MySQL / 后端端口 | 确认只绑 `127.0.0.1`，安全组不放行 3306/8080 | 编排默认已绑回环，云上仍要确认安全组 |
| HTTPS | 有域名时上 443 | 否则密码与 token 明文传输 |
| `BACKEND_MEM` | 按机器内存设 | 不设会导致 OOM 且无日志 |
| MySQL 持久性参数 | 保持 `innodb_flush_log_at_trx_commit=1`、`sync_binlog=1` | 编排里显式设了这两个值。改成 2/0 能把压测吞吐提高 15 倍，但崩溃可能丢最近 1 秒事务——**拿持久性换性能，不能为了跑分偷偷改** |
| 日志轮转 | 确认生效 | 已配 20MB × 7 天，落在 `backend-logs` 卷 |
| `deleted` 数据 | 定期归档 | 逻辑删除的数据永久保留；`sys_operation_log` / `sys_login_log` 只增不改，会持续增长 |
| 备份 | 定期 dump | 见下 |

备份与恢复（用 `.env` 里的密码，不写死在命令行）：

```bash
cd deploy

# 备份
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --databases "G14(1)"' > backup-$(date +%Y%m%d).sql

# 恢复
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < backup-20261111.sql
```

> `--single-transaction` 让 InnoDB 在不锁表的情况下拿到一致快照。不加的话备份期间有写入会导致数据不自洽。

## 7. nginx 配置要点

`deploy/nginx/default.conf` 一个 server 同时托管静态产物与反代 `/api/`，前后端同源——这是不做 CORS 配置的前提。

| 配置 | 值 | 为什么 |
|---|---|---|
| `listen 80; listen [::]:80;` | 同时监听 IPv4 与 IPv6 | **只写 `listen 80` 时容器会一直 unhealthy**：容器里 `localhost` 优先解析到 `::1`，健康检查走 IPv6 被拒，而宿主机访问其实正常，运维看到 unhealthy 容易误重启 |
| `upstream ... keepalive 32` | 后端长连接 | 不开 keepalive 高并发下会堆积大量 TIME_WAIT |
| `proxy_set_header X-Forwarded-For` | `$proxy_add_x_forwarded_for` | 后端 `RequestUtil` 优先取 XFF；不传则登录日志里全员是 `172.x` 容器地址 |
| `proxy_http_version 1.1` + `Connection ""` | — | 与 keepalive 配套，缺一不可 |
| `proxy_read_timeout 300s` | — | Excel 导出是流式响应，默认 60s 对大数据量不够 |
| `location /assets/` `expires 1y` + `immutable` | — | Vite 产物文件名带内容哈希，可永久缓存 |
| `location = /index.html` `no-store` | — | 否则用户拿到旧入口指向已删除的 chunk，白屏 |
| `try_files $uri $uri/ /index.html` | — | Vue Router 用 history 模式，刷新子路由不能 404 |
| `location = /healthz` | `return 200 "ok\n"` + `access_log off` | 给负载均衡/监控探活，不写日志 |
| `log_format main` 含 `$status` | — | **长期运行故障率的第二份证据**：`grep -c ' 5[0-9][0-9] ' access.log` ÷ 总行数。不能关日志 |

统计故障率：

```bash
total=$(docker compose logs frontend --no-log-prefix | wc -l)
errors=$(docker compose logs frontend --no-log-prefix | grep -c ' 5[0-9][0-9] ')
echo "故障率 = $errors / $total"
```

## 9. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose` 报 `required variable ... is missing a value` | 没建 `deploy/.env` 或键名错 | `cp .env.example .env` 并填两项必填 |
| 后端启动报 `Could not resolve placeholder 'APP_JWT_SECRET'` | 环境变量没传进容器 | 检查 `.env` 有没有这一项；`docker compose config` 看展开结果 |
| 后端启动报 `长度不足 32 字节，HS256 不安全` | 密钥太短 | 用 `openssl rand -base64 48` 重新生成 |
| 中文全变 `æ ¡å›­` | MySQL 客户端字符集是 latin1 | 确认 `LANG=C.UTF-8` 与 `client-charset.cnf` 都挂上了；**已初始化过的数据卷要 `down -v` 重建才会修好** |
| 日志里 `World-writable config file 'client-charset.cnf' is ignored` | Windows 挂载后文件权限变 777，MySQL 拒绝读取 | 只影响 Windows 本机调试，此时靠 `LANG=C.UTF-8` 仍然正确；Linux 服务器上 git 记录的是 644，不会出现 |
| 打开 `/swagger-ui.html` 看到的是首页 | nginx 的 `try_files` 把未知路径回落到了 `index.html` | 接口文档刻意不对外暴露，`deploy/nginx/default.conf` 已显式 `return 404`。要看文档请 `curl 127.0.0.1:8080/v3/api-docs` 或映射后端端口 |
| 后端容器反复重启，日志里没原因 | 内存超限被 OOM Killer 杀 | `docker inspect g14-backend --format '{{.State.OOMKilled}}'` 应为 false；调小 `BACKEND_MEM` 或加内存 |
| `docker compose ps` 里 frontend 一直 `(health: starting)` 或 `(unhealthy)` 但页面能开 | nginx 只监听 IPv4，`localhost` 解析到 `::1` | 确认 `default.conf` 里有 `listen [::]:80;` |
| 拉镜像卡住 / `failed to resolve source metadata ... EOF` | 镜像加速器失效 | 换 `/etc/docker/daemon.json` 里的 `registry-mirrors` |
| 页面能开但接口全 404 | nginx 没反代 `/api` 或 upstream 名字不匹配 | 检查 `location /api/` 与 `upstream campus_backend` |
| 刷新子路由 404 | 缺 `try_files ... /index.html` | 补上 |
| 登录日志里 IP 全是 `172.x` | 没传 `X-Forwarded-For` | 在 `location /api/` 补 `proxy_set_header` |
| 公网 IP 打不开，服务器本机 curl 正常 | 安全组/防火墙没放行 80 | 控制台加规则（见 1.7） |
| 大陆服务器用 80 端口被拦 | 未备案 | 换非 80 端口，或换香港/海外机房 |
| 启动报 `NoClassDefFoundError: com/alibaba/excel/ExcelWriter` | `cp.txt` 是旧的 / 落到了 `backend\backend\target\` | 用**绝对路径**重跑 `dependency:build-classpath`，确认 `(Get-Content backend\target\cp.txt -Raw) -match 'easyexcel'` |
| 启动报 `Illegal overloaded getter method ... ReflectionException` | 实体里手写 `isXxx()` 与 Lombok getter 冲突 | 改名（如 `anonymousEnabled()` / `builtinOnly()`） |
| `ERROR 1046 No database selected` | 执行 `source` 时没跟库名 | `mysql ... "g14(1)" -e "source ..."` |
| Excel 打开乱码 | `Content-Disposition` 没写 `filename*=UTF-8''` | 后端 `prepareResponse` 已处理，检查是否被改回 `filename=` |
| 学生进不了填写页（403） | 前端用了 `/surveys/{id}`，该路径需要 update/preview 权限 | 大厅跳转必须用 `shareCode` → `/fill/{code}` |
