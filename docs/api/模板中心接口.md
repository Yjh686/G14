# 模板中心接口（FR-TPL）

> 对应代码：`backend/src/main/java/com/yjh/backend1/module/template/`
> 对应前端：`frontend/G14/src/views/template/`、`frontend/G14/src/components/ShareTemplateDialog.vue`
> 冒烟脚本：`deploy/test/smoke_template.ps1`（13 组 135 条断言）

---

## 1. 这是什么

教师把自己的一份问卷「共享」成模板，管理员审核通过后，其他老师可以一键复制成自己的新问卷草稿，学生可以给模板打 1~5 星。

这里最容易搞错的一点：**模板不是指向问卷的引用，而是一份快照。**

共享的那一刻，后端把问卷当时的题目结构（题型、题干、说明、必答、字数上限、评分上限、选项文本）序列化成 JSON 存进 `survey_template.structure_json`。之后：

- 原问卷改题、删题、删卷 → 模板内容不变
- 别人用模板建出的新问卷改题 → 模板内容不变
- 模板里没有 question_id / option_id，只有题目顺序和选项文本

**为什么这么设计**：如果模板存 `source_survey_id` 然后每次实时读问卷，那么老师一改问卷，别人正在用的模板就跟着变了；更糟的是删掉来源问卷后模板会指向不存在的题目。快照换来的是「看到什么就是什么」。

## 2. 状态机

```
                    ┌──────────── 重新提交 ────────────┐
                    ▼                                │
  共享    ┌──────────────┐  管理员通过   ┌───────────┐ │
 ───────► │   PENDING    │ ────────────► │ APPROVED  │ │
          │   待审核      │               │  已通过    │ │
          └──────┬───────┘               └─────┬─────┘ │
                 │ 管理员驳回（必填原因）          │ 共享者下架
                 ▼                              ▼       │
          ┌──────────────┐               ┌───────────┐  │
          │   REJECTED   │               │  OFFLINE  │  │
          │   已驳回      │               │  已下架    │  │
          └──────────────┘               └───────────┘  │
                 │                              │       │
                 └──────── 共享者删除 ──────────┴───────┘
```

转移规则：

| 从 | 到 | 谁 | 条件 |
|---|---|---|---|
| — | PENDING | 教师/管理员（`template:share`） | 来源问卷是自己的且有题目 |
| PENDING | APPROVED | 管理员（`template:audit`） | — |
| PENDING | REJECTED | 管理员（`template:audit`） | **必须填审核意见** |
| REJECTED | PENDING | 共享者（`template:share`） | 重新提交，清空审核意见/审核人/审核时间 |
| APPROVED | OFFLINE | 共享者（`template:offline`） | — |
| REJECTED / OFFLINE | 删除（`deleted=1`） | 共享者（`template:share`） | 状态必须是这两个之一 |

几条刻意的限制：

- **审核只接受 APPROVED / REJECTED**。传 PENDING 等于「撤销审核」，会让已经被别人用过的模板凭空回到待审——真要撤，正确姿势是下架。
- **待审核的模板不能删除**。它正排在管理员的队列里，此时删掉会让审核记录凭空消失。
- **已通过的模板不能直接删**，必须先下架。避免「有人正在用，共享者一键清空」。
- 状态里**没有 DELETED**。删除统一由 `deleted=1` 表达，否则会出现 `status=DELETED` 但 `deleted=0` 这种两处状态打架的数据（和 `survey` 表同一套约定）。

## 3. 三层权限，缺一不可

这套接口的权限检查分三层，**任何一层单独存在都是漏洞**：

| 层 | 检查什么 | 在哪 |
|---|---|---|
| 方法级 | 你有没有这个功能权限码 | `@RequirePerm` 注解，`AuthInterceptor` 执行 |
| 视角级 | 你请求的 `scope` 是否配套 | `TemplateService.page()` |
| 数据级 | 这条模板是不是你的 | `TemplateService.requireOwned()` |

举两个必须三层都有的例子：

- `GET /api/templates?scope=audit` —— 光有 `template:browse` 不够，服务层再查一次 `template:audit`。
- `POST /api/templates/{id}/offline` —— 光有 `template:offline` 不够，还得是**你自己共享的**模板。

**模板没有 `*:all` 全量权限。** 管理员能审核、能看所有待审内容，但不能下架或删除别人的模板。这是刻意留的边界：审核是管理员的职责，替别人撤下已发布的模板不是。

## 4. 接口清单

| # | 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|---|
| 1 | GET | `/api/templates` | browse / share / audit | 列表，靠 `scope` 分视角 |
| 2 | GET | `/api/templates/{id}` | browse / share / audit | 详情（含 `structure`） |
| 3 | POST | `/api/templates` | `template:share` | 共享为模板 |
| 4 | POST | `/api/templates/{id}/resubmit` | `template:share` | 重新提交被驳回的模板 |
| 5 | POST | `/api/templates/{id}/offline` | `template:offline` | 下架 |
| 6 | DELETE | `/api/templates/{id}` | `template:share` | 删除（仅已驳回/已下架） |
| 7 | PUT | `/api/templates/{id}/audit` | `template:audit` | 审核通过 / 驳回 |
| 8 | POST | `/api/templates/{id}/use` | `template:use` | 复制成自己的新问卷草稿 |
| 9 | PUT | `/api/templates/{id}/rating?score=` | `template:rate` | 评分 1~5 |

统一响应格式 `{code, msg, data, timestamp, success}`，`code` 与 HTTP 状态码一致。

## 5. 列表接口 `GET /api/templates`

### 5.1 请求参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `scope` | string | `browse` | `browse` 模板中心 / `mine` 我共享的 / `audit` 审核队列 |
| `keyword` | string | — | 模糊匹配模板名称 |
| `category` | string | — | `TEACHING` / `ACTIVITY` / `SATISFACTION` / `OTHER` |
| `status` | string | 见下 | 状态筛选，**在 browse 视角下无效** |
| `order` | string | `rating` | `rating` 评分优先 / `latest` 最新 / `used` 最多使用 |
| `page` / `size` | int | 1 / 20 | `size` 上限 100 |

### 5.2 三种视角的差异

| 视角 | 需要权限 | status 默认 | status 可筛选 | 数据范围 |
|---|---|---|---|---|
| `browse` | 三选一即可 | **强制 APPROVED** | **否，传了也不生效** | 全部已通过的 |
| `mine` | `template:share` 或 `template:offline` | 全部状态 | 是 | `create_by = 自己` |
| `audit` | `template:audit` | `PENDING` | 是 | 全部共享者的 |

`browse` 视角的 `status` 是硬编码覆盖的，不是「默认值」——`?scope=browse&status=PENDING` 依然只返回 APPROVED。否则任何人都能通过改 URL 翻出别人的待审内容。

### 5.3 排序

- `rating`（默认）：`rating_avg DESC, rating_count DESC, id DESC`
- `latest`：`id DESC`
- `used`：`use_count DESC, id DESC`

默认排序**刻意不加 `rating_avg IS NOT NULL`**。MySQL 里 `NULL` 最小，`DESC` 自然排最后，所以没人评分的新模板会排在后面但**不会消失**。如果加了 `IS NOT NULL` 过滤，新模板永远等不到第一个评分——死锁。

### 5.4 响应

```json
{
  "code": 200,
  "data": {
    "records": [
      {
        "id": 3,
        "title": "课程满意度调查模板",
        "description": "适合期末教学评价",
        "category": "TEACHING",
        "categoryLabel": "教学反馈",
        "sourceSurveyId": 12,
        "questionCount": 3,
        "anonymousDefault": 1,
        "limitOnceDefault": 1,
        "status": "APPROVED",
        "statusLabel": "已通过",
        "auditRemark": null,
        "auditBy": 1,
        "auditByName": "系统管理员",
        "auditTime": "2026-11-08 18:30:00",
        "submitTime": "2026-11-08 18:20:00",
        "ratingCount": 2,
        "ratingAvg": 4.0,
        "myScore": 5,
```

两个字段要特别注意：

## 6. 详情 `GET /api/templates/{id}`

在列表字段基础上多一个 `structure`：

```json
{
  "structure": [
    {
      "questionType": "SINGLE",
      "title": "你对本课程的总体满意度？",
      "description": null,
      "isRequired": 1,
      "maxLength": null,
      "ratingMax": null,
      "sortNo": 1,
      "options": ["非常满意", "满意", "一般"]
    },
    {
      "questionType": "MULTIPLE",
      "title": "你最喜欢哪种授课方式？",
      "isRequired": 0,
      "sortNo": 2,
      "options": ["案例讨论", "实验实操", "分组汇报"]
    }
  ]
}
```

**注意和问卷接口的 `QuestionVO` 的区别**：

| | 问卷 `QuestionVO` | 模板 `TemplateQuestionVO` |
|---|---|---|
| 题目 ID | 有（`id`） | **无** |
| 选项结构 | `[{id, content, sortNo}]` | **`string[]`** |
| 用途 | 编辑、作答绑定 | 只读展示 + 复制建卷 |

前端因此**不能复用 `QuestionRenderer`**（它的 v-model 绑的是选项 id），模板详情和审核抽屉都是自己写的只读列表。

**未通过审核的模板可见性**：

| 访问者 | 结果 |
|---|---|
| 共享者本人 | 200（能看到自己的待审/被驳回模板） |
| 持有 `template:audit` 的管理员 | 200 |
| 其他任何人 | **404**「模板不存在或未通过审核」 |

这里返回 404 而不是 403，是因为 403 等于告诉对方「这里确实有个模板，只是不给你看」——存在性就泄露了。

## 7. 共享 `POST /api/templates`

```json
{
  "sourceSurveyId": 12,
  "title": "课程满意度调查模板",
  "description": "适合期末教学评价",
  "category": "TEACHING",
  "anonymousDefault": 1,
  "limitOnceDefault": 1
}
```

| 字段 | 必填 | 校验 |
|---|---|---|
| `sourceSurveyId` | 是 | 必须是你自己的问卷 |
| `title` | 是 | 1~120 字 |
| `description` | 否 | ≤500 字 |
| `category` | 否 | 空则继承来源问卷 |
| `anonymousDefault` | 否 | **Integer(1/0)**，不是 boolean；空则继承 |
| `limitOnceDefault` | 否 | 同上 |

**题目结构不从请求体接收。** 后端自己去查来源问卷的当前题目，拍成快照。这样「前端传的结构」和「问卷真实结构」不可能不一致。

错误码：

| 场景 | 码 | 文案 |
|---|---|---|
| 来源问卷不存在 | 404 | 问卷不存在或已被删除 |
| 共享别人的问卷 | 403 | 无权操作他人的问卷 |
| 问卷没有题目 | 400 | 该问卷还没有题目，无法共享为模板 |
| 缺模板名 | 400 | — |
| 没有 `template:share` | 403 | 无权限执行该操作 |

## 8. 审核 `PUT /api/templates/{id}/audit`

```json
{ "auditStatus": "APPROVED" }
{ "auditStatus": "REJECTED", "auditRemark": "描述太简略，请补充适用场景" }
```

| `auditStatus` | `auditRemark` | 结果 |
|---|---|---|
| `APPROVED` | 可空 | 立即对所有人可见 |
| `REJECTED` | **必填** | 共享者在「我共享的模板」里能看到这句话 |
| `PENDING` | — | 400「审核结果只能是 APPROVED 或 REJECTED」 |
| 其他 | — | 400「未知的模板状态：x」 |

只有当前状态是 `PENDING` 才能审核，重复审核 → 400「只有待审核的模板可以审核，当前状态：已通过」。

## 9. 评分 `PUT /api/templates/{id}/rating?score=4`

- `score` 走 query 参数，范围 1~5 的整数（不为一个整数单独定义请求体 DTO）
- 一人一模板一票，**重复调用是改分，不是新增**
- 只能给 `APPROVED` 的模板评分
- 分数没变时直接返回，不写库也不记日志

计数维护靠两个字段：

```
rating_count  票数
rating_sum    分数总和
rating_avg    DECIMAL(3,2) STORED 生成列 = rating_sum / rating_count
```

**为什么不直接存 `avg`**：改分时用 `rating_sum + (new - old)` 就行，不需要 `avg * count` 反算（反算会引入浮点漂移）；而且生成列可以建索引，直接支持「按评分排序」。

**为什么不建 `template_rating` 的删除接口**：一个人撤回自己的评分会让「平均分」跳动得很莫名，课程项目里没有这个需求。改分足以表达「我改主意了」。

> 提示：新模板无人评分时 `rating_avg = NULL`。想让它排前面就得有人先评——这是排序规则里不加 `IS NOT NULL` 的原因，见 5.3。

## 10. 使用模板 `POST /api/templates/{id}/use`

需要 `template:use` + `survey:create` 两个权限（建卷动作本身还要走一遍问卷模块的权限）。

响应是**新问卷的 `SurveyDetailVO`**（和 `POST /api/surveys` 同结构），前端拿到 `id` 直接跳编辑器。

内部流程：

1. 模板状态必须 `APPROVED`
2. 调 `SurveyService.create()` 建草稿（标题/说明/分类/匿名/限填来自模板）
3. 把 `structure` 逐题转成 `QuestionSaveRequest`，调 `SurveyService.saveQuestions()`
4. `use_count = use_count + 1`（用 `setSql` 原子自增，不做读-改-写）
5. 写操作日志

新问卷的特征：

| 字段 | 值 |
|---|---|
| `status` | `DRAFT` |
| `shareCode` | `null`（要自己发布才生成） |
| `createBy` | 当前用户（不是模板共享者） |
| `answerCount` | 0 |
| 题目/选项 | 与模板快照一致，ID 全是新的 |

**复用 `SurveyService.saveQuestions()` 而不是自己插表**，是为了自动获得题库那套校验（选择题 ≥2 选项、字数上限、评分上限）。否则模板结构一旦有脏数据，会在这里被静默写进问卷。

## 11. 错误码速查

| 码 | 典型场景 |
|---|---|
| 400 | 参数校验失败、状态不允许该操作、驳回不填原因、评分越界、scope/order 未知 |
| 401 | 未登录、令牌失效 |
| 403 | 无功能权限、非本人操作（无权操作他人的模板 / 问卷） |
| 404 | 模板不存在、未过审的模板对非本人不可见 |
| 409 | 重复下架、评分并发冲突 |

## 12. 数据表

### `survey_template`

| 字段 | 说明 |
|---|---|
| `title` / `description` / `category` | 模板自身信息，不随来源问卷变化 |
| `source_survey_id` | 仅作溯源记录，**业务上不读它** |
| `question_count` | 冗余，列表页直接显示，避免读 JSON |
| `anonymous_default` / `limit_once_default` | 使用模板建卷时的默认设置 |
| `structure_json` | **题目快照**（JSON NOT NULL） |
| `status` | PENDING / APPROVED / REJECTED / OFFLINE |
| `audit_remark` / `audit_by` / `audit_time` | 审核痕迹 |
| `submit_time` | 提交审核时间 |
| `rating_count` / `rating_sum` | 评分计数与总和 |
| `rating_avg` | **STORED 生成列**，`CASE WHEN rating_count=0 THEN NULL ELSE ROUND(rating_sum/rating_count,2) END` |
| `use_count` | 被使用次数 |

> 生成列在实体里必须标 `@TableField(insertStrategy = NEVER, updateStrategy = NEVER)`，否则 MyBatis-Plus 会把它写进 INSERT，MySQL 报 `The value specified for generated column ... is not allowed`。

### `template_rating`

| 字段 | 说明 |
|---|---|
| `template_id` / `user_id` | 联合唯一索引 `uk_template_user` |
| `score` | TINYINT 1~5 |

唯一索引是**并发下的最后防线**：两个人同一瞬间首次评分，两边都查到「没有旧评分」，都走 INSERT，第二个会撞唯一键——代码里 catch `DuplicateKeyException` 转 409「您已经评过分了，请刷新后重试」，计数不会多算。

## 13. 为什么模板结构不拆表

模板只做两件事：整块读（详情/审核/使用）、整块写（共享时插入一次）。**没有任何「跨模板按题目查询」的需求**，所以拆成 `template_question` + `template_option` 只会多两次 JOIN 和一次差量同步。

对照反例：`answer_item` 就必须拆表，因为统计要按题目聚合、要按问卷筛题。

同理，`structure_json` 里存选项**文本**而不存选项 ID —— 存 ID 会在来源问卷改删选项后指向不存在的东西。
