# 系统配置接口（FR-CFG）

> 对应需求：`docs/requirements/SRS-需求规格说明书.md` 4.11 节
> FR-CFG-01 站点信息 / FR-CFG-02 默认密码与密码策略 / FR-CFG-03 键值对存储 + 前端读取公开配置
> 实现：`backend/src/main/java/com/yjh/backend1/module/config/`
> 数据表：`sys_config`（见 `deploy/sql/05_schema_config.sql`）
> 权限码：`config:manage`（仅 ADMIN）

---

## 1. 一句话设计

**一张键值表 + 一个 `is_public` 标志。** 公开的项（站点名、公告、页脚、密码规则）进 `GET /api/config/public`，未登录也能读；私有的项（默认密码）连管理员读取时都打码，永远不出现在公开接口里。

之所以不拆成「站点信息表 + 安全策略表」，是因为这两类东西追加配置的概率一样高（学校想加个「联系电话」、想加个「是否允许学生注册」），拆表就得多写一套增删改查。键值表的代价是值都是字符串，所以加了 `config_type` 让前端知道该渲染成文本框、开关还是密码框。

## 2. 数据模型

```
sys_config
  id             BIGINT PK AUTO
  config_key     VARCHAR(64)  UNIQUE          -- 业务主键，如 site.name
  config_value   TEXT                          -- 一律存字符串
  config_type    VARCHAR(16)  STRING/TEXT/NUMBER/BOOLEAN/PASSWORD
  group_name     VARCHAR(32)  SITE/SECURITY/OTHER
  description    VARCHAR(255)                  -- 给人看的用途说明
  is_public      TINYINT      1=公开项（未登录可读） 0=私有项
  builtin        TINYINT      1=内置（可改不可删）
  create_by / create_time / update_by / update_time / deleted
  UNIQUE KEY uk_key (config_key)               -- 注意：不含 deleted
  KEY idx_group (group_name, deleted)
```

### 2.1 唯一键为什么不带 `deleted`

最直觉的写法是 `UNIQUE KEY uk_key (config_key, deleted)`，让「删掉后还能重建同名键」。但同一个键**第二次**被删除时会和上一行的 `(key, 1)` 相撞——逻辑删除的行不会消失，删两次就插入失败了。

改成只挂 `config_key`，代价是新建立时可能撞上墓碑行。解决办法是**复活**：新建时用 `SELECT ... WHERE config_key=? LIMIT 1` 绕过 `@TableLogic`（普通 `selectOne` 会被自动拼上 `deleted=0`，看不见墓碑行），若查到 `deleted=1` 的行就执行 `revive` 把值覆盖回去并置 `deleted=0`。

所以：

- `SysConfigMapper.selectByKeyIncludeDeleted(key)` 是必须的，不能用 `selectOne`
- `SysConfigMapper.revive(...)` 是必须的，不能用 `updateById`（`@TableLogic` 会拼 `deleted=0`，墓碑行永远更新不到）

### 2.2 内置的 10 项

| config_key | 值 | 类型 | 分组 | 公开 |
|---|---|---|---|---|
| `site.name` | 校园问卷系统 | STRING | SITE | ✅ |
| `site.logo` | （空） | STRING | SITE | ✅ |
| `site.announcement` | （空） | TEXT | SITE | ✅ |
| `site.footer` | （空） | STRING | SITE | ✅ |
| `security.default-password` | G14@init2025 | **PASSWORD** | SECURITY | ❌ |
| `security.password.min-length` | 8 | NUMBER | SECURITY | ✅ |
| `security.password.max-length` | 32 | NUMBER | SECURITY | ✅ |
| `security.password.require-letter` | 1 | BOOLEAN | SECURITY | ✅ |
| `security.password.require-digit` | 1 | BOOLEAN | SECURITY | ✅ |
| `security.password.require-special` | 0 | BOOLEAN | SECURITY | ✅ |

内置值必须与代码兜底默认值（`PasswordRules.DEFAULT`、`"G14@init2025"`）**保持一致**。否则「库里有这行」和「库里没这行」会走两套行为，出问题时非常难排查。

> `security.default-password` 不是公开项。它的值是「所有没改过密码的账号的钥匙」，泄露等于把钥匙挂在门口。

## 3. 接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/config/public` | **无（免登录）** | 公开键值对，登录页用 |
| GET | `/api/config` | `config:manage` | 全量配置，按分组归拢 |
| PUT | `/api/config` | `config:manage` | 批量保存 |
| POST | `/api/config` | `config:manage` | 新增自定义项 |
| DELETE | `/api/config/{id}` | `config:manage` | 删除自定义项 |

## 4. 接口详情

### 4.1 `GET /api/config/public` —— 公开配置

**免登录**。已加入 `AuthInterceptor.WHITE_LIST`。

响应：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "site.name": "校园问卷系统",
    "site.logo": "",
    "site.announcement": "",
    "site.footer": "",
    "security.password.min-length": "8",
    "security.password.max-length": "32",
    "security.password.require-letter": "1",
    "security.password.require-digit": "1",
    "security.password.require-special": "0"
  }
}
```

**为什么这个接口不能加权限**：登录页在用户还没有令牌的时候就要渲染站点名、公告和密码规则提示。加 `@RequirePerm` 等于把登录页标题变成「请先登录」，非常荒谬。

过滤条件 `is_public = 1` 写在 SQL 里而不是内存里筛——写错成内存筛还有救，写成「查全部再删掉几个键」迟早漏一个。

### 4.2 `GET /api/config` —— 全量配置

响应按 `groupName` 归拢：

```json
{
  "code": 200,
  "data": {
    "SITE": [
      {
        "id": 1,
        "configKey": "site.name",
        "configType": "STRING",
        "groupName": "SITE",
        "description": "站点名称，显示在登录页、侧边栏与浏览器标题",
        "configValue": "校园问卷系统",
        "masked": false,
        "publicVisible": true,
        "builtin": true,
        "updateTime": "2026-11-09 10:30:00"
      }
    ],
    "SECURITY": [
      {
        "id": 6,
        "configKey": "security.default-password",
        "configType": "PASSWORD",
        "configValue": "******",
        "masked": true,
        "publicVisible": false,
        "builtin": true
      }
    ]
  }
}
```

**PASSWORD 类型的值是 `******` 而不是 `null`**。用 `null` 的话前端分不清「这项有值但我不给你看」和「这项从来没设过」，后者是配置损坏需要报警的状态。

### 4.3 `PUT /api/config` —— 批量保存

请求体是数组：

```json
[
  { "configKey": "site.name", "configValue": "某某大学问卷系统" },
  { "configKey": "security.password.min-length", "configValue": "10" }
]
```

| 字段 | 说明 |
|---|---|
| `configKey` | 必填，必须是已存在的键 |
| `configValue` | 新值；**PASSWORD 类型原样传回 `******` 视为不修改** |
| `configType` / `groupName` / `description` / `publicVisible` | 可选，省略则沿用库里的值 |

响应 `data` 是**真正发生变更的项数**（`Integer`）。值没变的项不写库、不刷 `update_time`——否则「保存」一次会把十项的更新时间全部洗成当前时间，之后无法从 `update_time` 判断到底哪项动过。

错误：

| 场景 | code | msg |
|---|---|---|
| 键不存在 | 404 | `配置项不存在：xxx` |
| NUMBER 类型但不是数字 | 400 | `该项要求是数字，当前值：abc` |
| BOOLEAN 类型但值非法 | 400 | `该项只能是 0/1/true/false，当前值：maybe` |
| PASSWORD 非空但少于 6 位 | 400 | `密码长度不能少于 6 位` |

> PASSWORD 只挡 6 位下限，完整强度交给 `PasswordPolicy`。理由是管理员有时确实需要一个临时弱密码，配置层拦太死会导致「改不回去」。

保存后 `min/max` 若自相矛盾（max < min），只打 `log.warn` 不抛异常。值已经落库了，这时候抛错只会让管理员看到一个失败提示而不知道其实已经改坏——不如让他看到成功，再去日志里发现警告。

### 4.4 `POST /api/config` —— 新增自定义项

```json
{
  "configKey": "site.contact",
  "configValue": "010-12345678",
  "configType": "STRING",
  "groupName": "OTHER",
  "description": "页脚联系电话",
  "publicVisible": true
}
```

| 校验 | 规则 |
|---|---|
| 键名 | `^[a-zA-Z][a-zA-Z0-9._-]{1,63}$` |
| 类型 | 必须在 `STRING/TEXT/NUMBER/BOOLEAN/PASSWORD` 内 |
| 分组 | 必须在 `SITE/SECURITY/OTHER` 内 |
| 键已存在（未删除） | 409 `配置键已存在：xxx` |
| 键已存在（已删除） | 200，**复活那一行**并覆盖值 |

新建的项 `builtin = false`，可删除。

### 4.5 `DELETE /api/config/{id}` —— 删除

| 场景 | code | msg |
|---|---|---|
| 不存在 | 404 | `配置项不存在` |
| `builtin = 1` | 400 | `内置配置项不能删除，只能修改它的值` |
| `builtin = 0` | 200 | 逻辑删除 + 清空缓存 |

内置项不许删的原因：删掉后代码会退回兜底值，"我明明在这里配了 8 位" 和 "配置项不见了所以是 8 位" 从界面看一模一样。想恢复默认就改值，不要删。

## 5. 密码策略如何真正生效（FR-CFG-02）

改 `security.password.*` 之后，下面四处必须同时跟随，否则管理员会看到「配置里写 12 位但某处仍按 8 位报错」：

| 位置 | 接入方式 |
|---|---|
| 自助注册 `POST /api/auth/register` | `PasswordPolicy.check(pwd, configService.passwordRules())` |
| 自助改密 `POST /api/auth/password` | 同上 |
| 管理员建用户 `POST /api/users` | 同上 |
| 批量导入 `POST /api/users/import` | `PasswordPolicy.validate(pwd, configService.passwordRules())` |

**踩过的坑（必须记住）**：DTO 上原本写的是 `@Size(min = 8, max = 32)`，改配置到 12 之后注册接口报的是新文案、建用户接口报的却是「密码长度需为 8~32 位」——因为 Bean Validation 在进入 Service 之前就拦下了。

现在的约定：

> **密码类 DTO 只写 `@Size(max = 64)` 挡物理上限，绝不写 `min` 或复杂度。**
> 长度与复杂度一律由 `PasswordPolicy` 按系统配置判定。

### 缓存

`ConfigService` 内部有 5 分钟 TTL 的 `Map<String, CacheEntry>`。保存/新建/删除后立即 `cache.clear()`，所以管理员改完马上生效（`smoke_config.ps1` 第 5 节已验证）。

`passwordRules()` 读到的 min/max 会 **clamp** 到合法区间（min 6~32、max 8~64），并保证 max ≥ min。越界值不报错而是夹紧——否则管理员手滑写成 `min-length=100`，所有人都注册不了，包括他想用来登录修配置的那个账号，直接锁死自己。

## 6. 前端如何用公开配置

`src/stores/config.ts` 把公开配置装进 Pinia store，暴露四个 computed：

| 名称 | 来源键 | 用途 |
|---|---|---|
| `siteName` | `site.name` | 登录页标题、侧边栏品牌、浏览器标题 |
| `announcement` | `site.announcement` | 登录页公告条（空串不显示） |
| `footer` / `logo` | `site.footer` / `site.logo` | 预留给页脚与 Logo |
| `passwordRules` / `passwordRuleText` | `security.password.*` | 注册/改密/建用户表单的前端预检与提示 |

加载时机：**路由守卫 `beforeEach` 的第一行** `await useConfigStore().load()`。放在守卫里而不是 `main.ts` 是因为：

1. 浏览器标题在守卫之后由 `afterEach` 设置，那时必须有站点名；
2. `load()` 内部有 `pending` 合并，并发导航只会发一次请求，后续都是空转；
3. 失败静默（`catch` 里什么都不做），登录页不能因为公告接口挂了就打不开。

管理员保存配置后，`ConfigView.save()` 会额外调 `configStore.load(true)` 强制刷新，让侧边栏与标题立即跟上，不用刷新页面。

## 7. 错误码速查

| code | 场景 |
|---|---|
| 200 | 成功 |
| 400 | 键名不合规 / 类型不在白名单 / NUMBER 非数字 / BOOLEAN 非 0-1 / 删内置项 / PASSWORD 太短 |
| 401 | 未带令牌访问管理接口 |
| 403 | 无 `config:manage` |
| 404 | 配置项不存在 |
| 409 | 新建时键已存在 |
| 500 | 未预期异常 |
