# 统计分析与数据导出接口

> 模块：FR-STAT（统计与分析）+ FR-EXP（数据导出）
> 代码位置：`backend/src/main/java/com/yjh/backend1/module/stat/`、`module/export/`
> 验证脚本：`deploy/test/smoke_stat.ps1`（15 组 119 条断言）

---

## 1. 口径先行：三个数字定义

统计模块最容易出问题的地方不是代码，是口径。接口返回的所有数字都遵守下面三条，**前端文案必须与之一致**，否则用户会觉得「数字算错了」。

### 1.1 只统计有效答卷

| 项目 | 定义 | 来源 |
|---|---|---|
| 回收总数 `totalSheetCount` | 该问卷收到的全部答卷（含被标记无效的） | `answer_sheet where survey_id=? and deleted=0` |
| 有效答卷 `validSheetCount` | `is_valid = 1` 的答卷 | 同上 + `is_valid=1` |
| 参与统计 | **只有有效答卷** | 所有 `questions[]` 里的数字都只来自有效答卷 |

被标记无效的答卷会在下次查询时立刻从统计中消失（不缓存、不预聚合），恢复后立刻回来。

### 1.2 分母是「该题有效作答人数」

每个选项的 `ratio` = 该选项被选次数 ÷ **该题有效作答人数**，不是选项总数、也不是回收总数。

由此产生两个必然现象，属正确行为：

- **多选题各选项 `ratio` 相加 > 1**。一道多选有 4 个选项，5 个人每人平均选 2 项，占比之和会到 200%。
- **各题 `answeredCount` 可能不同**。非必答题有人跳过，跳过的人不进该题分母。

前端因此有一条硬规则：**多选不画饼图**（饼图扇形在数学上不成立），只画柱状图并显式提示「占比之和会超过 100%」。

### 1.3 没人作答时返回 0，不返回 NaN

| 场景 | 返回 |
|---|---|
| 该题无人作答 | `answeredCount = 0`，所有 `count / ratio = 0` |
| 评分题无人作答 | `average = 0.0`，`distribution` 仍是 `1..ratingMax` 全档且全为 0 |
| 问卷无有效答卷 | 整卷 `validSheetCount = 0`，各题结构完整、数字为 0，HTTP 200 |
| 问卷还没有题目 | `questions = []`，HTTP 200 |

**绝不因为没数据而报错或返回 500**——这是 R-STAT-2 的硬要求。

## 2. 接口清单

| # | 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|---|
| 1 | GET | `/api/surveys/{surveyId}/stats` | `stat:read:self` \| `stat:read:all` | 整卷统计，一次拿全 |
| 2 | GET | `/api/surveys/{surveyId}/stats/questions/{questionId}` | 同上 | 单题统计 |
| 3 | GET | `/api/surveys/{surveyId}/export/answers` | `export:self` \| `export:all` | 导出 xlsx（**不返回 JSON**） |

三个接口都走同一套数据范围判定：`*:all` 直接放行；否则必须有 `*:self` **且** `create_by = 当前用户`，否则 403。

## 3. 整卷统计

`GET /api/surveys/{surveyId}/stats`

### 3.1 响应

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "surveyId": 56,
    "surveyTitle": "统计测试问卷",
    "category": "TEACHING",
    "categoryLabel": "教学反馈",
    "status": "PUBLISHED",
    "anonymous": true,
    "totalSheetCount": 5,
    "validSheetCount": 5,
    "publishedTime": "2026-11-08 10:28:41",
    "generatedAt": "2026-11-08 10:31:02",
    "questions": [ /* QuestionStatsVO[] */ ]
  },
  "timestamp": 1794105000000,
  "success": true
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `anonymous` | boolean | 匿名问卷。**注意与其他模块不一致**：这里是真的 boolean，问卷 VO 里是 Integer 1/0 |
| `totalSheetCount` | int | 回收总数（含无效） |
| `validSheetCount` | int | 有效答卷数 = `survey.answer_count` |
| `generatedAt` | string | 统计生成时间，前端可展示「数据截至」 |
| `questions` | array | 按 `sortNo` 升序 |

### 3.2 QuestionStatsVO

五种题型共用一个结构，按 `questionType` 决定哪个子结构有值：

| `questionType` | `options` | `text` | `rating` |
|---|---|---|---|
| `SINGLE` | ✅ | `null` | `null` |
| `MULTIPLE` | ✅ | `null` | `null` |
| `TEXT` | `null` | ✅ | `null` |
| `TEXTAREA` | `null` | ✅ | `null` |
| `RATING` | `null` | `null` | ✅ |

公共字段：

| 字段 | 说明 |
|---|---|
| `questionId` / `sortNo` / `title` / `description` | 题目本身 |
| `answeredCount` | **该题**的有效作答人数（各题可能不同） |
| `validSheetCount` | 整卷有效答卷数，用于展示「有 N 人未答」 |

### 3.3 选择题：`options[]`

```json
{ "optionId": 152, "content": "大一", "count": 2, "ratio": 0.4 }
```

- 顺序与题目选项的 `sortNo` 一致；
- `count` 是**选了这个选项的人数**（同一人多选同一选项只算一次，代码里用 `HashSet` 去重防脏数据）；
- `ratio` 保留 4 位小数。

### 3.4 文本题：`text`

```json
{
  "answeredCount": 5,
  "answers": [ { "text": "作业量有点大", "submitTime": "2026-11-08 10:29:03" } ],
  "truncated": false,
  "words": [ { "word": "作业", "count": 3 } ]
}
```

| 字段 | 说明 |
|---|---|
| `answers` | **按提交时间倒序**，最多 200 条 |
| `truncated` | `true` 表示超过 200 条被截断，前端应提示「完整内容请导出」 |
| `words` | 高频词，最多 20 个，每个至少出现 2 次 |
| 无 `fillerName` | 统计页刻意不给填写人（匿名卷无身份，实名卷的明细在答卷详情里看） |

**词频是 2-gram 而非分词**：连续汉字按两字滑窗切分（「作业量有点大」→ 作业/业量/量有/有点/点大），单字丢弃，连续英文数字整体成词并小写；停用词表约 30 个（这个/那个/我们/老师/同学/课程/觉得/希望/建议/…）。

> 为什么不上分词库：jieba/ansj 会把课程项目拖成「装依赖 → 调词典 → 版本冲突」的循环，而这里的目标只是「快速看一眼大家在说什么」，2-gram 足够且零依赖。词频仅供参考，不替代阅读原文。

### 3.5 评分题：`rating`

```json
{
  "answeredCount": 5,
  "average": 4.2,
  "ratingMax": 5,
  "distribution": [
    { "star": 1, "count": 0, "ratio": 0 },
    { "star": 2, "count": 0, "ratio": 0 },
    { "star": 3, "count": 1, "ratio": 0.2 },
    { "star": 4, "count": 2, "ratio": 0.4 },
    { "star": 5, "count": 2, "ratio": 0.4 }
  ]
}
```

`distribution` **必定包含 1..ratingMax 全部档位**，没人选的档也返回 `count: 0`。这是为了让前端画柱状图时不用补空档，图表不会因为缺档而横向错位。

`average` 保留 2 位小数（接口给较精确的值，避免二次舍入累积误差）；**页面与 Excel 汇总行展示时保留 1 位小数**（验收标准 2.3、SRS R-TPL-2 的要求）。

## 4. 单题统计

`GET /api/surveys/{surveyId}/stats/questions/{questionId}`

返回单个 `QuestionStatsVO`。用于未来做「点一题拉一次」的懒加载；当前前端一次拉整卷再本地切题，此接口保留。

| 情况 | 响应 |
|---|---|
| 正常 | 200 + QuestionStatsVO |
| 题目不属于该问卷 | 404 `题目不存在或已从该问卷移除` |
| 问卷不存在 | 404 `问卷不存在或已被删除` |
| 无权限 | 403 `无权操作他人的问卷` / `您没有执行该操作的权限` |

## 5. 导出

`GET /api/surveys/{surveyId}/export/answers`

### 5.1 这是唯一不遵守 `{code,msg,data}` 约定的接口

成功时直接返回二进制流：

```
HTTP/1.1 200 OK
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="export.xlsx"; filename*=UTF-8''%E6%95%99%E5%AD%A6...%E9%97%AE%E5%8D%B7_20261108103147.xlsx
Access-Control-Expose-Headers: Content-Disposition
```

- `filename` 给一个 ASCII 兜底名 `export.xlsx`；
- `filename*`（RFC 5987）带真正的中文名，前端必须优先读它，否则下载下来叫 `export.xlsx`；
- 失败时（未开始写流前）仍返回统一 JSON 结构。

> 取舍：流已经开始写之后出错无法再改状态码，所以导出内部的所有校验（权限、归属、问卷存在）都在 `prepareResponse` 之前完成。

### 5.2 文件名规则

`{问卷标题}_{yyyyMMddHHmmss}.xlsx`

- 标题里的 `\ / : * ? " < > |` 替换成 `_`；
- 标题截断到 60 字符；
- 时间戳由后端生成（不用前端时间，避免时区误差）。

例：`教学质量反馈问卷_20261108103147.xlsx`

### 5.3 两个 Sheet

#### Sheet「明细」：一行一份答卷，一列一道题

| 序号 | 提交时间 | 答卷状态 | 填写人 | 学号/工号 | 第1题 … | 第2题 … |
|---|---|---|---|---|---|---|
| 1 | 2026-11-08 10:29:03 | 有效 | 李同学 | student | 非常满意 | 案例讨论、实验实操 |

**匿名问卷没有「填写人」「学号/工号」两列**（R-EXP-1），表头直接不生成这两列，不是留空。

单元格内容规则：

| 题型 | 单元格 |
|---|---|
| SINGLE | 选项文本 |
| MULTIPLE | 选项文本用 `、` 拼接 |
| TEXT / TEXTAREA | 原文 |
| RATING | 数字 |

**只导出有效答卷**。无效答卷不在明细里——这与统计口径一致，避免「表里 10 行、页面说 8 份」的对不上。

#### Sheet「汇总」：每题选项频次与占比

| 题号 | 题目 | 题型 | 项目 | 人数 | 占比 |
|---|---|---|---|---|---|
| 第1题 | 你所在的年级？ | 单选 | 大一 | 2 | 40.00% |
| | | | 大二 | 2 | 40.00% |
| | | | 大三 | 1 | 20.00% |
| | | | 【有效作答人数】 | 5 | |
| 第5题 | 推荐学弟学妹选这门课吗？ | 评分 | 5 星 | 2 | 40.00% |
| | | | 4 星 | 2 | 40.00% |
| | | | … | | |
| | | | 【平均分 4.2，参评 5 人】 | | |
| 口径 | 仅统计有效答卷 | — | 有效 5 份 / 回收 5 份 | | |

- 选择题按选项拆行，每题末行 `【有效作答人数】`；
- 评分题按星级拆行，末行给平均分与参评人数；
- 文本题给作答条数与高频词（`高频词：作业(3)、实验(2)`）；
- 最后一行固定写口径，避免表格脱离界面后被误读。

### 5.4 空问卷也导出两个 Sheet

零答卷时 EasyExcel 不会创建「明细」Sheet，导出的 xlsx 会只剩「汇总」，打开像丢了一半。后端在写完明细后检查 `total == 0`，补一行占位：

| 序号 |
|---|
| 暂无答卷 |

### 5.5 流式写出

`EasyExcel` 底层是 POI 的 SXSSF，按 200 份一页从库里捞：

1. `SELECT ... LIMIT 200 OFFSET n` 取一页答卷；
2. 一次 `IN (...)` 查这一页的全部作答明细；
3. 写进 Sheet 后丢弃这一页的对象。

内存占用与答卷总数无关，只与页大小有关。**不要改成先 `selectList` 全量再写**——1000 份 × 20 题就是 2 万个对象，课程项目的 512MB 堆容易直接 OOM。

## 6. 错误码

| HTTP | 场景 | 文案 |
|---|---|---|
| 400 | `surveyId` 非数字 | `参数类型错误：surveyId` |
| 401 | 未登录 / 令牌失效 | `未登录或登录已过期` |
| 403 | 学生访问统计或导出 | `您没有执行该操作的权限` |
| 403 | 教师访问他人问卷 | `无权操作他人的问卷` |
| 404 | 问卷不存在 / 已删除 | `问卷不存在或已被删除` |
| 404 | 题目不属于该问卷 | `题目不存在或已从该问卷移除` |
| 500 | 导出过程异常 | 通用错误提示（不暴露堆栈） |

## 7. 权限与数据范围

| 角色 | `stat:read:self` | `stat:read:all` | `export:self` | `export:all` |
|---|---|---|---|---|
| ADMIN | ✅ | ✅ | ✅ | ✅ |
| TEACHER | ✅ | ❌ | ✅ | ❌ |
| STUDENT | ❌ | ❌ | ❌ | ❌ |

- 权限码只是第一道门，第二道是归属：`*:all` 命中就直接放行（ADMIN 可以看任何人的问卷统计）；否则必须 `*:self` **且** `create_by = 当前用户`。
- 只有权限码不够：管理员给某教师加了 `stat:read:all`，他就能看所有人的统计——这是设计意图（超级权限），不是漏洞。

---

## 8. 为什么不做预聚合表

R-STAT-1 明确要求按需查询。预聚合表（`survey_stat` 存每题每选项的人数）看起来快，但会引入一个无法消除的窗口：

> 用户提交答卷 → `answer_count + 1` → 统计表还没重算 → 页面显示旧数字

为了避免这个窗口，就得在提交、标记无效、恢复、删除四条路径上都触发重算，还得处理重算失败的回滚。课程级数据量（问卷 < 200、单卷答卷 < 500）下，现算一次整卷统计的实测耗时在 100ms 内，没有必要付出这个复杂度。

真到了数据量撑不住的规模，把 `StatService` 的实现换成一条聚合 SQL 即可，**接口签名不变**，前端零改动。
