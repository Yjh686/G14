# 认证与用户管理 接口文档

> 模块：账号认证（AUTH）+ 用户管理（USER）+ 角色权限（RBAC）
> 版本：v1.0 ／ 最后更新：2025 学期
> 服务地址：`http://localhost:8080`，统一前缀 `/api`

---

## 0. 通用约定

### 0.1 统一响应体

所有接口（含错误）都返回同一结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {},
  "timestamp": 1794061161206,
  "success": true
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | **与 HTTP 状态码一致**（200/400/401/403/404/409/500），便于前端只判断一处 |
| msg | string | 面向用户的中文提示，可直接弹 toast |
| data | any | 业务数据，无数据时为 `null` |
| timestamp | long | 服务器毫秒时间戳 |
| success | boolean | `code == 200` 的等价便捷字段 |

> 设计理由：业务码与 HTTP 状态码统一，避免「HTTP 200 + body.code=500」这类需要双重判断的写法，也让浏览器 DevTools / 网关日志能直接看出成败。

### 0.2 鉴权

除白名单外，所有接口都需要在请求头携带 JWT：

```
Authorization: Bearer <token>
```

白名单（免登录）：

| 路径 | 说明 |
| --- | --- |
| `POST /api/auth/login` | 登录 |
| `POST /api/auth/register` | 自助注册 |
| `GET /api/health` | 健康检查 |

> 兼容用法：也支持 `?token=xxx` 查询参数，仅用于浏览器直接下载导出文件的场景。

### 0.3 状态码语义

| code | 含义 | 典型场景 |
| --- | --- | --- |
| 200 | 成功 | — |
| 400 | 参数错误 / 业务规则不允许 | 密码强度不足、驳回未填理由 |
| 401 | 未登录、令牌失效 | 无 token、token 过期、改密后旧 token |
| 403 | 已登录但无权限 / 状态不允许 | 学生访问用户管理、账号被禁用 |
| 404 | 资源不存在 | 用户 id 不存在、接口路径拼错 |
| 405 | 请求方法不支持 | 用 GET 请求只接受 POST 的接口 |
| 409 | 冲突 | 用户名重复、账号锁定、重复追加权限 |
| 500 | 服务端异常 | 未捕获异常（响应中不返回堆栈） |

### 0.4 时间格式

所有 `LocalDateTime` 字段统一序列化为 `yyyy-MM-dd HH:mm:ss`（东八区），如 `"lastLoginTime": "2026-11-07 22:18:10"`。

## 1. 认证接口 `/api/auth`

### 1.1 登录

`POST /api/auth/login` ｜ 免登录

**请求体**

```json
{ "username": "teacher", "password": "Teacher@123" }
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| username | string | 是 | 非空，学号/工号或管理员账号 |
| password | string | 是 | 非空 |

**成功响应**

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 43200,
    "userId": 2,
    "username": "teacher",
    "realName": "张老师",
    "roleCode": "ROLE_TEACHER",
    "roleName": "教师",
    "mustChangePassword": false,
    "permissions": ["survey:create", "survey:publish:self", "..."]
  }
}
```

`expiresIn` 单位为秒（默认 720 分钟 = 43200 秒）。前端可据此做提前续期或到期提醒。

**失败场景**

| code | msg | 触发条件 |
| --- | --- | --- |
| 400 | 参数校验提示 | username/password 为空 |
| 401 | 账号或密码错误，还可尝试 N 次 | 密码错误且未达上限 |
| 401 | 账号或密码错误 | 账号不存在（**与密码错文案一致**） |
| 403 | 账号已被禁用，请联系管理员 | `status = 0` |
| 403 | 账号正在等待管理员审核，请耐心等候 | `audit_status = 0` |
| 403 | 注册申请未通过审核：{审核意见} | `audit_status = 2` |
| 409 | 账号因多次登录失败已被锁定，请 N 分钟后再试 | 锁定期内再次登录 |
| 409 | 密码错误次数过多，账号已锁定 15 分钟 | 第 5 次密码错误触发锁定 |

> 安全要点：账号不存在与密码错误返回**完全相同**的文案，且内部对不存在的账号也执行一次 BCrypt 校验（DUMMY_HASH），防止通过响应时间枚举学号。真实失败原因只写入 `sys_login_log`，供管理员排查。

**锁定策略**：连续失败 5 次（`app.security.max-login-fail`）锁定 15 分钟（`app.security.lock-minutes`）；锁定期间即使密码正确也不放行；成功登录后失败计数与锁定时间清零。

---

### 1.2 退出登录

`POST /api/auth/logout` ｜ 需登录

无请求体。仅记录一条退出日志。

**响应**：`{"code":200,"msg":"已退出登录","data":null}`

> 说明：JWT 无状态，服务端不做黑名单。真正让令牌失效靠 `token_version`（改密、被重置密码、被禁用、被删除时自增）。前端退出时应**自行清除本地 token**。

---

### 1.3 自助注册

`POST /api/auth/register` ｜ 免登录

**请求体**

```json
{
  "username": "2025001",
  "password": "Reg2025abc",
  "realName": "王同学",
  "role": "STUDENT",
  "department": "计算机学院2025级",
  "phone": "13800138000"
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| username | string | 是 | 4~64 位，仅字母/数字/下划线/点/短横线 |
| password | string | 是 | 8~32 位，不含空白，必须同时含字母和数字 |
| realName | string | 是 | 非空 |
| role | string | 是 | **只能是** `STUDENT` 或 `TEACHER` |
| department | string | 否 | ≤ 100 |
| phone | string | 否 | 空或 `^1[3-9]\d{9}$` |

**响应**：`{"code":200,"msg":"注册申请已提交，请等待管理员审核","data":null}`

**失败场景**

| code | msg |
| --- | --- |
| 400 | 密码长度需为 8~32 位 / 密码不能包含空格 / 密码必须同时包含字母和数字 |
| 400 | 身份只能是 STUDENT 或 TEACHER |
| 409 | 该学号/工号已被注册，请直接登录或联系管理员 |
| 409 | 该手机号已被使用 |

> 注册出来的账号 `audit_status = 0`（待审核），**未审核不能登录**。这是「账号由 ADMIN 导入或注册后审核」决策的落地方式：任何人不经管理员同意都进不来。

---

### 1.4 修改密码

`POST /api/auth/password` ｜ 需登录

**请求体**

```json
{ "oldPassword": "G14@init2025", "newPassword": "Test2024abc" }
```

**成功响应**：结构同登录，返回**新 token**

```json
{ "code": 200, "msg": "密码修改成功", "data": { "token": "...", "mustChangePassword": false, "...": "..." } }
```

**失败场景**

| code | msg |
| --- | --- |
| 400 | 原密码不正确 |
| 400 | 新密码不能与原密码相同 |
| 400 | 密码长度需为 8~32 位 / 密码必须同时包含字母和数字 |

> 关键行为：改密成功后服务端 `token_version + 1`，**所有旧令牌立即失效**（旧 token 访问任何接口返回 401「登录状态已失效，请重新登录」），同时返回新 token，当前设备无需重新登录。这样「改完密码别的设备还挂着」的问题被彻底堵住。
>
> `must_change_password = 1` 的账号（管理员新建 / 被重置密码）只能访问 `/api/auth/password`、`/api/auth/logout`、`/api/auth/me`、`/api/auth/password-status`，访问其它接口一律 403「首次登录或密码已被重置，请先修改密码」。

---

### 1.5 查询改密状态

`GET /api/auth/password-status` ｜ 需登录

**响应**：`{"code":200,"msg":"操作成功","data":true}`

前端在路由守卫里调用，`true` 则强制跳转改密页。

### 1.6 当前用户信息

`GET /api/auth/me` ｜ 需登录

**响应**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "userId": 2,
    "username": "teacher",
    "realName": "张老师",
    "roleCode": "ROLE_TEACHER",
    "roleName": "教师",
    "department": "计算机学院",
    "phone": null,
    "email": null,
    "mustChangePassword": false,
    "lastLoginTime": "2026-11-07 22:17:28",
    "permissions": ["..."]
  }
}
```

> 刻意**不返回** `passwordHash`、`tokenVersion`、`loginFailCount`、`lockedUntil`。前端菜单与按钮显隐应基于 `permissions` 数组，而不是硬编码角色名。

### 1.7 修改个人资料

`PUT /api/auth/profile` ｜ 需登录

**请求体**（各字段均可选，传即更新）

```json
{ "realName": "张老师", "phone": "13900139000", "email": "zhang@example.edu", "department": "计算机学院" }
```

**响应**：`{"code":200,"msg":"资料已更新","data":{ ...同 me... }}`

**失败场景**

| code | msg |
| --- | --- |
| 409 | 该手机号已被其他账号使用 |

> 普通用户只能改自己的资料；`username`（学号/工号）、`roleCode`、`status` 一律不可自助修改。

## 2. 用户管理接口 `/api/users`（ADMIN）

以下接口全部需要对应权限码，学生/教师调用返回 403。

### 2.1 用户列表（分页）

`GET /api/users` ｜ 权限 `user:list`

**查询参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| keyword | string | — | 模糊匹配 username 或 realName |
| status | int | — | 1 启用 / 0 禁用 |
| auditStatus | int | — | 0 待审核 / 1 通过 / 2 驳回 |
| roleCode | string | — | `ROLE_ADMIN` / `ROLE_TEACHER` / `ROLE_STUDENT` |
| page | int | 1 | 页码 |
| size | int | 20 | 每页条数，**上限 100** |

**响应**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "records": [ { "id": 2, "username": "teacher", "realName": "张老师", "roleCode": "ROLE_TEACHER", "roleName": "教师", "status": 1, "auditStatus": 1, "mustChangePassword": 0, "department": "计算机学院", "lastLoginTime": "2026-11-07 22:17:28", "createTime": "2026-11-07 22:11:53" } ],
    "total": 1, "page": 1, "size": 10, "pages": 1
  }
}
```

> `roleCode/roleName` 通过批量查询角色表填充，避免 N+1。列表项同样不含任何密码/令牌字段。

### 2.2 用户详情

`GET /api/users/{id}` ｜ 权限 `user:list` 或 `user:audit`

不存在时 404「用户不存在」。

### 2.3 新建用户

`POST /api/users` ｜ 权限 `user:create`

**请求体**

```json
{ "username": "20241087", "realName": "李四", "roleCode": "ROLE_STUDENT", "password": "可选", "department": "计算机学院", "phone": "", "email": "", "remark": "" }
```

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| username | 是 | 4~64，`^[A-Za-z0-9_.-]+$`，全局唯一 |
| realName | 是 | 非空 |
| roleCode | 是 | `ROLE_ADMIN` / `ROLE_TEACHER` / `ROLE_STUDENT` |
| password | 否 | 8~32；**不填则用系统默认密码** |
| phone | 否 | 空或手机号格式 |

**响应**：`data` 为新建用户的 UserVO。

行为说明：

- 管理员建的账号 `audit_status = 1`，**无需再审核**即可登录；
- 未填密码时使用 `app.security.default-password`（当前 `G14@init2025`），并置 `must_change_password = 1`，用户首次登录必须改密；
- 重复 username → 409「该学号/工号已存在」。

### 2.4 修改用户

`PUT /api/users/{id}` ｜ 权限 `user:update`

**请求体**：`realName / department / phone / email / remark / roleCode`（`username` 不可改）

特殊约束：

| 场景 | 结果 |
| --- | --- |
| 改自己的 roleCode | 400「不能修改自己的角色，请让其他管理员操作」 |
| 把最后一名启用 ADMIN 降级 | 409「系统必须保留至少一名启用状态的管理员」 |

> 角色变更会先删后插 `sys_user_role`，并清空该用户的权限缓存，下一次请求即生效。

### 2.5 删除用户

`DELETE /api/users/{id}` ｜ 权限 `user:delete`

逻辑删除（`deleted = 1`），并在删除前 `token_version + 1`，被删账号的在线会话立即失效。

| 场景 | 结果 |
| --- | --- |
| 删除自己 | 400「不能删除自己的账号」 |
| 删除最后一名启用 ADMIN | 409「系统必须保留至少一名管理员」 |

### 2.6 启用 / 禁用

`PUT /api/users/{id}/status?status=0|1` ｜ 权限 `user:status`

| 场景 | 结果 |
| --- | --- |
| 禁用自己 | 400「不能禁用自己的账号」 |
| 禁用最后一名启用 ADMIN | 409 |
| 禁用成功 | `token_version + 1`，该用户**当前已登录的会话立刻 401/403** |

### 2.7 审核注册申请

`PUT /api/users/{id}/audit` ｜ 权限 `user:audit`

**请求体**

```json
{ "auditStatus": 1, "auditRemark": "" }
```

| auditStatus | 含义 |
| --- | --- |
| 1 | 通过，可登录 |
| 2 | 驳回，**必须填 auditRemark** |

| 场景 | 结果 |
| --- | --- |
| auditStatus 传 0 或其它值 | 400「审核状态只能是 1(通过) 或 2(驳回)」 |
| 驳回但 auditRemark 为空 | 400「驳回时必须填写审核意见」 |

> 驳回原因会原样展示给该用户在登录时的报错里（「注册申请未通过审核：学号不在名册内」），所以审核意见要写得能让人看懂。

### 2.8 重置密码

`POST /api/users/{id}/reset-password` ｜ 权限 `user:reset-password`

无请求体。

**响应**

```json
{ "code": 200, "msg": "密码已重置", "data": "G14@init2025" }
```

`data` 为重置后的明文默认密码，供管理员当面/线下告知本人。

行为：密码重置为默认密码 + `must_change_password = 1` + `token_version + 1`（强制下线）。用户下次登录必须先改密。

## 3. 角色与权限接口 `/api/rbac`（ADMIN）

### 3.1 角色列表

`GET /api/rbac/roles` ｜ 权限 `role:list`

返回 `[{ "id":1, "code":"ROLE_ADMIN", "name":"系统管理员", "description":"...", "builtin":1 }]`

### 3.2 权限码（按模块分组）

`GET /api/rbac/permissions` ｜ 权限 `role:list`

返回 `{ "问卷管理": [ {...SysPermission...} ], "答题": [ ... ] }`，供权限配置页面渲染分组勾选框。

### 3.3 查询用户生效权限

`GET /api/rbac/users/{userId}/permissions` ｜ 权限 `user:grant`

返回排序后的权限码数组（**角色权限 ∪ 追加权限** 的去重并集）。

### 3.4 查询用户追加权限

`GET /api/rbac/users/{userId}/extra-permissions` ｜ 权限 `user:grant`

只返回通过 `sys_user_permission` 单独追加的部分，用于「额外授权」区域回显。

### 3.5 追加权限

`POST /api/rbac/users/{userId}/permissions?permCode=survey:create` ｜ 权限 `user:grant`

**响应**：`{"code":200,"msg":"权限已追加","data":null}`

| 场景 | 结果 |
| --- | --- |
| 权限码不存在 | 400「权限码不存在：xxx」 |
| 已有该追加权限 | 409「该用户已拥有此追加权限」 |

> 典型用途：**学生干部要发问卷** → 给该学生追加 `survey:create`，而不是新建一个「学生干部」角色。追加权限独立于角色，后续改角色也不会丢。追加后立即清缓存，下一个请求就生效。

### 3.6 撤销追加权限

`DELETE /api/rbac/users/{userId}/permissions?permCode=survey:create` ｜ 权限 `user:grant`

| 场景 | 结果 |
| --- | --- |
| 没有这条追加记录 | 404「该用户没有这条追加权限」 |

> 只能撤追加的那部分；角色自带的权限撤不掉（要改角色权限关系），避免误操作把教师变成不能发卷。

## 7. 前端接入要点

1. **登录后**：存 token（建议 localStorage）+ 存 `permissions` 数组，跳转首页。
2. **路由守卫**：无 token → 登录页；`mustChangePassword === true` → 强制改密页；访问需要权限的路由时检查 `permissions.includes('xxx')`。
3. **请求拦截器**：统一加 `Authorization: Bearer <token>`。
4. **响应拦截器**：`code === 401` → 清 token 跳登录页（文案用后端返回的 `msg`，别写死「登录已过期」，因为可能是「改密后旧令牌失效」）；`code === 403` 且有 `mustChangePassword` 相关文案 → 跳改密页；其它非 200 → `ElMessage.error(msg)`。
5. **按钮级权限**：用 `v-if="hasPerm('user:create')"` 之类的指令/方法，而不是判断角色名。
