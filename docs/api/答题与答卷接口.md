# 答题与答卷 接口文档

> 模块：填写与草稿（FILL） + 答卷管理（ANS）
> 版本：v1.0
> 服务地址：`http://localhost:8080`，统一前缀 `/api`
> 通用约定（响应体、鉴权、状态码、时间格式）见 `docs/api/认证与用户管理接口.md` 第 0 章，本文不再重复。

## 1. 设计要点（读接口前先看这段）

### 1.1 路径按「视角」分段，不靠权限码猜

| 路径段 | 视角 | 典型调用者 |
| --- | --- | --- |
| `/api/hall/**` | 找问卷、填报、看**自己的**记录 | 学生、教师（教师也能填别人的卷） |
| `/api/answers/**` | 看**别人的**答卷、标记、删除 | 教师（自己的卷）、ADMIN（全部） |
| `/api/surveys/{id}/answer-summary` | 回收概览 | 教师（自己的卷）、ADMIN（全部） |

会碰到他人数据的接口全部落在 `/api/answers` 下，评审时不用先翻权限注解就能看出风险点。

### 1.2 匿名是「后端裁剪」，不是「前端隐藏」

匿名问卷在 `answer_sheet` 表里**照样存 `user_id`**（有它才能做「限填一次」和「我的填写记录」），
但所有对外响应都要经 `AnswerService.toSheetVO()` **这一个出口**把身份字段置 null。

| 出口 | 匿名时的行为 |
| --- | --- |
| `GET /api/answers`（答卷列表） | `userId` / `fillerName` / `fillerUsername` 全为 `null` |
| `GET /api/answers/{sheetId}`（答卷详情） | 同上，作答内容照常返回（发布者需要看答案做统计） |
| `GET /api/hall/my-answers`（我的记录） | `contentVisible = false` |
| `GET /api/hall/my-answers/{sheetId}`（我的回执） | `items` 与 `questions` 均为 `null`，只给回执 |
| 操作日志 | **不写**「某用户提交了某匿名问卷」 |
| IP / UA | `answer_sheet` 表**不存**，避免与访问日志交叉反推身份 |

> 新增任何返回答卷的接口，都必须走 `toSheetVO()`，不要自己 `new AnswerSheetVO()` 再 copyProperties。

### 1.3 「能不能填」由后端算，前端不拼时间

`fillable = status == PUBLISHED && now ∈ [startTime, endTime)`
- `startTime == null` → 立即开始
- `endTime == null` → 长期有效

不依赖定时任务改状态（R-PUB-3），所以任何时刻的判定都是一次纯函数计算。

`fill-state` 里的 `reason` 是**机器码**，前端按码做文案与按钮禁用，不要解析中文：

| reason | 含义 | 前端建议 |
| --- | --- | --- |
| `""`（空串） | 可填 | 显示「开始填写」 |
| `NOT_STARTED` | 未到开始时间 | 提示开始时间 |
| `PAUSED` | 已暂停回收 | 灰按钮 +「已暂停回收」 |
| `CLOSED` | 已结束 | 灰按钮 +「问卷已结束」 |
| `EXPIRED` | 已过截止时间 | 灰按钮 +「已过截止时间」 |
| `ALREADY_SUBMITTED` | 我填过了 | 显示「已提交」+ 回执入口 |

### 1.4 限填一次靠数据库唯一索引，不靠代码判断

`answer_sheet` 上有一列生成列 + 唯一键：

```sql
uniq_user BIGINT UNSIGNED GENERATED ALWAYS AS
  (CASE WHEN limit_once = 1 AND deleted = 0 THEN user_id ELSE NULL END) STORED,
UNIQUE KEY uk_survey_user (survey_id, uniq_user)
```

- `limit_once = 1` → 生成列等于 `user_id`，唯一键生效，同一人第二次插入直接 `DuplicateKeyException`
- `limit_once = 0` → 生成列为 `NULL`，MySQL 唯一索引允许多个 NULL，重复填写不受限

代码里的预检查（返回 409「你已经提交过该问卷」）只是给用户友好提示，
**并发场景下真正的防线是这条唯一索引**；`submit` 里 `catch (DuplicateKeyException)` 转 409 就是这个原因。

### 1.5 回收概览的口径（三个人会算出三个数，所以写死在这）

| 字段 | 口径 |
| --- | --- |
| `total` | 已回收答卷数，**含**已标记无效的（「交了多少份」） |
| `validCount` | 有效答卷数（= `survey.answer_count`，统计口径） |
| `invalidCount` | 被标记无效的答卷数 |
| `completionRate` | `validCount ÷ expectedCount`，保留 4 位小数，分母为 0 时返回 `0`（不返回 NaN） |
| `expectedCount` | **启用状态的学生账号总数** |

> `expectedCount` 是**近似口径**。本期没有「指定填答班级/名单」功能，无法知道某份问卷到底该由谁填，
> 只能拿全校启用学生数当分母。等填答范围功能上线后，分母换成实际名单人数，字段语义不变。
> 答辩时如果被问「完成率怎么算的」，就照这张表回答。

`survey.answer_count` 的语义是**有效答卷数**，四条路径必须成对修改：

| 动作 | answer_count |
| --- | --- |
| 提交成功 | +1 |
| 标记无效 | -1 |
| 恢复有效 | +1 |
| 删除有效答卷 | -1 |

## 3. 接口详情

### 3.1 问卷大厅 `GET /api/hall`

查询参数：

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | int | 否 | 1 | 页码 |
| `size` | int | 否 | 12 | 每页条数，上限 100 |
| `keyword` | string | 否 | — | 标题模糊匹配 |
| `category` | string | 否 | — | 分类筛选，非法值当「不筛选」 |

只返回 `status = PUBLISHED` 且当前时间落在 `[startTime, endTime)` 内的问卷，
按 `published_time DESC, id DESC` 排序。

响应 `data`：`PageResult<HallSurveyVO>`，每条在 `SurveyVO` 基础上追加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `myStatus` | string | `NOT_STARTED` / `DRAFT` / `SUBMITTED` |
| `draftTime` | datetime | 我的草稿最后保存时间，无草稿为 `null` |
| `submitTime` | datetime | 我的提交时间，未提交为 `null` |

> `myStatus` 与 `fillable` 是两个概念，卡片两个都要用：
> 问卷开着但我已提交 → 按钮「已提交」；问卷暂停了我还没填 → 按钮「已暂停回收」。

### 3.2 填写状态 `GET /api/hall/surveys/{surveyId}/fill-state`

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `surveyId` | long | 问卷 ID |
| `surveyTitle` | string | 标题 |
| `fillable` | boolean | 现在能不能填 |
| `reason` | string | 不可填的机器码，可填时为空串 |
| `submitted` | boolean | 我是否已提交 |
| `sheetId` | long | 我的答卷 ID，未提交为 `null` |
| `submitTime` | datetime | 我的提交时间 |
| `draftAnswers` | array | 草稿内容（`AnswerInput` 数组），无草稿为 `null` |
| `draftTime` | datetime | 草稿保存时间 |

错误：`404 问卷不存在或已被删除`。

### 3.3 草稿

**读** `GET /api/hall/surveys/{surveyId}/draft` → `data` 为 `List<AnswerInput>`，无草稿返回空数组。

**写** `PUT /api/hall/surveys/{surveyId}/draft`

```json
{
  "answers": [
    { "questionId": 1, "optionValues": [1] },
    { "questionId": 2, "optionValues": [5, 6] },
    { "questionId": 3, "textValue": "2023" }
  ]
}
```

响应：`{ "savedAt": "2026-11-07 23:09:31" }`，前端用它显示「已保存于 …」。

草稿的校验**刻意宽松**，因为「没答完」正是草稿的语义：

| 情况 | 行为 |
| --- | --- |
| 缺必答题 | 不校验 |
| 题型不合法 / 选项越界 | 不校验 |
| 文本超过 `maxLength` | **截断**后保存 |
| `questionId` 不属于本问卷 | **静默丢弃**该条 |
| 同一题重复提交 | 只保留最后一条 |
| 问卷不可填（暂停/结束/过期） | `400`，同提交 |
| 已提交且限填一次 | `409 你已经提交过该问卷，不能再保存草稿` |

前端建议 5 秒防抖自动保存（FR-FILL-04）。

### 3.4 提交 `POST /api/hall/surveys/{surveyId}/submit`

请求体同草稿。

响应 `data` 为 `AnswerSheetVO`（见 3.8），`msg = "提交成功，感谢你的参与"`。

校验顺序与对应错误（**全部 400，除重复提交为 409**）：

| 场景 | 状态码 | 文案 |
| --- | --- | --- |
| 问卷不可填 | 400 | `问卷已暂停回收，暂时无法填写` / `问卷已结束，无法再填写` / `问卷已过截止时间，无法再填写` / `问卷尚未开始，请到开始时间后再来填写` |
| 重复提交（限填一次） | 409 | `你已经提交过该问卷，不能重复填写` |
| 问卷无题目 | 400 | `该问卷还没有题目，无法提交` |
| 作答为空 | 400 | `至少回答一道题才能提交` |
| 必答缺失 | 400 | `还有必答题未作答：第 1 题「…」、第 2 题「…」、第 4 题「…」 等 4 道题`（≤3 条全列，否则折叠） |
| 同题多份作答 | 400 | `同一道题提交了多份作答：{id}` |
| 题目不属于本卷 | 400 | `题目 {id} 不属于该问卷` |
| 单选不是 1 项 | 400 | `第 N 题「…」 是单选题，必须且只能选择 1 项` |
| 多选 0 项 | 400 | `第 N 题「…」 是多选题，至少选择 1 项` |
| 多选选项重复 | 400 | `第 N 题「…」 的选项重复提交：{id}` |
| 选项属于别的题 | 400 | `第 N 题「…」 的选项 {id} 不属于该题` |
| 文本超长 | 400 | `第 N 题「…」 的作答超过 {max} 字上限（当前 {n} 字）` |
| 评分题没给分 | 400 | `第 N 题「…」 是评分题，必须给出分值` |
| 评分越界 | 400 | `第 N 题「…」 的评分必须在 1~{max} 之间（当前 {n}）` |

题目标签格式统一为 `第 {sortNo} 题「{题干前 14 字}…」`，前端可直接把这条 msg 弹在表单顶部并滚动到对应题。

### 3.5 我的填写记录 `GET /api/hall/my-answers`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `isValid` | int | `1` 仅有效 / `0` 仅无效 / 不传=全部 |
| `page` / `size` | int | 默认 1 / 20 |

响应 `data`：`PageResult<MyAnswerVO>`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sheetId` | long | 答卷 ID |
| `surveyId` | long | 问卷 ID |
| `surveyTitle` | string | 问卷标题 |
| `surveyStatus` | string | 问卷当前状态 |
| `submitTime` | datetime | 提交时间 |
| `isValid` | int | 1 有效 / 0 无效 |
| `contentVisible` | boolean | **匿名卷为 `false`**，前端据此隐藏「查看详情」 |

### 3.6 我的回执 `GET /api/hall/my-answers/{sheetId}`

只能查自己的，别人的返回 `404 答卷不存在`（不返回 403，避免通过状态码探测他人答卷 ID）。

匿名问卷：`items` 与 `questions` 均为 `null`，只返回回执字段（FR-FILL-08）。
实名问卷：返回完整作答内容与题目结构。

### 3.7 答卷列表 `GET /api/answers`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `surveyId` | long | **是** | 不传返回 `400 必须指定问卷 ID` |
| `isValid` | int | 否 | 1 有效 / 0 无效 / 不传全部 |
| `order` | string | 否 | `submit_desc`（默认）/ `submit_asc` |
| `page` / `size` | int | 否 | 默认 1 / 20，size 上限 100 |

数据范围：

1. 有 `answer:read:survey:all`（ADMIN）→ 不做归属判断；
2. 否则需有 `answer:read:survey:self` 且问卷 `createBy == 当前用户`；
3. 问卷属于他人 → `403 无权操作他人的问卷`；
4. 问卷不存在 → `404 问卷不存在或已被删除`。

### 3.8 答卷详情 `GET /api/answers/{sheetId}`

响应 `data`：`AnswerSheetDetailVO`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | long | 答卷 ID |
| `surveyId` | long | 问卷 ID |
| `surveyTitle` | string | 问卷标题 |
| `anonymous` | boolean | 是否匿名 |
| `submitTime` | datetime | 提交时间 |
| `isValid` | int | 1 / 0 |
| `invalidReason` | string | 无效原因 |
| `userId` | long | **匿名卷为 `null`** |
| `fillerName` | string | **匿名卷为 `null`** |
| `fillerUsername` | string | **匿名卷为 `null`** |
| `items` | array | 逐题作答 `QuestionAnswerVO` |
| `questions` | array | 题目结构，便于前端按题号渲染 |

`QuestionAnswerVO`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `questionId` | long | 题目 ID |
| `questionType` | string | 题型 |
| `questionTitle` | string | 题干 |
| `optionValues` | array\<long\> | 选中的选项 ID |
| `optionTexts` | array\<string\> | 选中的选项文本（**已翻译，前端不用再查字典**） |
| `textValue` | string | 文本作答 |
| `numberValue` | int | 评分值 |
| `answered` | boolean | 是否作答 |

### 3.9 回收概览 `GET /api/surveys/{surveyId}/answer-summary`

响应 `data` 见 1.5 的口径表，另含 `surveyId` / `surveyTitle` / `anonymous`。

### 3.10 标记无效 `PUT /api/answers/{sheetId}/invalidate?reason=刷单`

`reason` 可选，最长 255 字。响应 `data` 为更新后的 `AnswerSheetVO`。

错误：`409 该答卷已被标记为无效`、`404 答卷不存在`。

### 3.11 恢复有效 `PUT /api/answers/{sheetId}/restore`

错误：`409 该答卷当前已是有效状态`、`404 答卷不存在`。

### 3.12 删除答卷 `DELETE /api/answers/{sheetId}`

软删除（`deleted = 1`），仅 `answer:delete`（ADMIN）。删除后详情与列表均不可见，若答卷有效则 `answer_count - 1`。

## 4. 数据表

| 表 | 说明 |
| --- | --- |
| `answer_sheet` | 答卷主表。`limit_once` 是**提交时快照**（不能实时读 survey，否则发布者事后改设置会让历史答卷的唯一索引语义漂移）；`uniq_user` 生成列 + `uk_survey_user` 唯一键做并发防线；不记 IP/UA |
| `answer_item` | 作答明细，一题一行。`option_values` 用 JSON 数组而非单独选项表：单选 1 个、多选 N 个，拆表要多插 N 行且统计要 GROUP BY 两次 |
| `survey_draft` | 草稿，唯一键 `(survey_id, user_id)`，`answers_json` 存原样 JSON。不参与统计与导出，提交成功后删除 |

> `answer_item.optionValues` 在 Java 侧靠 `@TableName(autoResultMap = true)` + `JacksonTypeHandler` 反序列化。
> 因此 `AnswerItemMapper` **只继承 `BaseMapper`，不写自定义 `@Select`** —— 自定义 `@Select` 默认不套用 MyBatis-Plus 生成的 resultMap，会出现「查回来是字符串」的隐性 bug。

## 5. 状态码速查

| 码 | 本题域典型场景 |
| --- | --- |
| 200 | 正常 |
| 400 | 校验失败（必答缺失、题型不符、选项越界、超长、评分越界）、问卷不可填、缺 `surveyId` |
| 401 | 未登录 / 令牌失效 |
| 403 | 无权限码；教师读他人问卷的答卷 |
| 404 | 问卷不存在、答卷不存在、查他人回执 |
| 409 | 重复提交（限填一次）、已提交后存草稿、重复标记无效、重复恢复 |
