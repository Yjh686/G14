## 3. 七个关键设计

### 3.1 公开配置放 Pinia，不放组件本地状态

站点名要出现在**三个地方**：登录页、侧边栏、浏览器标题。各组件自己 `onMounted` 各调一次接口的后果是：

1. 页面加载时标题先闪「校园问卷系统」再变成真名；
2. 浏览器标题在路由守卫里改，**那里根本没有组件实例**，组件本地状态够不着。

所以放 store，并在路由守卫第一行 `await load()`。`load()` 内部有 `pending` 变量合并并发调用：

```ts
let pending: Promise<void> | null = null
async function load(force = false) {
  if (loaded.value && !force) return
  if (pending) return pending   // 并发导航只发一次请求
  pending = publicConfigApi.get().then(...).finally(() => { pending = null })
  return pending
}
```

失败时 `catch` 留空，`loaded` 保持 `false`，下次导航会重试。站点名退回 `'校园问卷系统'`——登录页不能因为一个公告接口 500 就打不开。

### 3.2 保存是「编辑副本 + 全量提交」

页面维护两份数据：

- `groups`：服务端原样返回的分组数据，只读，用于判断「哪些键存在」和「原值是什么」
- `edit`：`configKey → 当前输入值` 的扁平副本，`v-model` 绑的是它

点保存时才把 `dirtyKeys`（`edit[k] !== 原值` 的键）拼成数组提交。

这么做的理由：管理员改到一半关掉页面，线上配置不会被半成品覆盖。如果做成「每个输入框 `@change` 就提交」，改 min-length 的瞬间所有人就按新规则校验了，而管理员可能只是想改完再一起验证。

按钮上带改动计数（「保存（3）」），没有改动时按钮 `disabled`，避免误点后看到「已保存 0 项」这种让人怀疑的提示。

### 3.3 PASSWORD 的掩码 `******` 是「未修改」的哨兵值

`ConfigVO.masked === true` 时，`configValue` 是字面量 `******`。保存时如果用户没动这个输入框，提交上去的还是 `******`，后端识别为「不修改」并 `continue`。

为什么不用 `null` 表示「不修改」：

- `null` 在 JSON 里和「字段缺失」在前端很难区分；
- 用 `null` 的话，输入框就显示空白，管理员会误以为这项没设置过。

界面上还会在这类输入框下面加一行黄字：「当前值为 `******`，保持原样提交表示不修改」。

### 3.4 密码规则文案与校验都要跟着配置走

`src/utils/dict.ts` 的 `validatePassword` 从「写死 8~32」改成接受 `rule: PasswordRule` 参数：

```ts
export function validatePassword(value: string, rule: PasswordRule = DEFAULT_PASSWORD_RULE): string | null
```

保留默认参数是为了单测和「配置还没加载」的兜底。所有调用点（注册、改密、建用户）都必须传 `config.passwordRules`。

> 这一项在前端也踩过一次：注册页文案改了但校验没改，结果输入 10 位密码时提示「12~32 位」但表单不拦，用户点到提交才收到后端 400。

### 3.5 分组顺序写死，不用后端返回的顺序

后端返回的是 `Map<String, List<ConfigVO>>`，JSON 里键的顺序取决于 `LinkedHashMap` 的插入顺序，而插入顺序取决于 SQL 的返回顺序——不可依赖。

前端 `GROUP_ORDER = ['SITE', 'SECURITY', 'OTHER']` 固定顺序，`sections` computed 按它过滤。这样「站点信息」永远在「安全策略」上面。

### 3.6 内置项只显示「内置」标签，不给删除按钮

`builtin === true` 时操作列渲染为空。不是把按钮 `disabled`——`disabled` 的按钮会让管理员反复点击并怀疑界面卡住了；直接不渲染更清楚。

页面顶部还有一句说明：「内置项可以改值但不能删除（删掉会让代码兜底值生效，行为变得难以排查）」。

### 3.7 公开配置预览做成抽屉，只读

「查看公开配置」按钮打开 `el-drawer`，直接调 `publicConfigApi.get()`（不是从 `groups` 里筛 `publicVisible`）。理由：要验证的正是「**未登录**能拿到什么」，从已登录的全量数据里筛是自欺欺人——万一后端的 `is_public` 过滤写错了，这个预览也发现不了。

`e2e-config.mjs` 第 9 组断言的就是这个抽屉里**不包含** `security.default-password`。

## 4. 页面结构

```
.page
├── .page-header
│   ├── 标题 + 说明
│   └── 按钮组：查看公开配置 / 还原改动 / 保存（N）
├── el-skeleton（loading 时）
└── 每个分组一张 el-card
    ├── header：分组中文名 + 分组代码 tag
    └── .cfg-row × N（grid: 260px | 1fr | 60px）
        ├── .cfg-meta：键名 + 内置/公开/已加密 tag + 说明
        ├── .cfg-input：按 configType 渲染
        │   ├── BOOLEAN  → el-switch（绑定 edit[k] === '1'）
        │   ├── TEXT     → el-input textarea 2 行 + 字数统计
        │   ├── PASSWORD → el-input type=password
        │   └── 其他     → el-input（NUMBER 用 type=number）
        └── .cfg-ops：删除（仅 builtin=false）
```

`el-switch` 必须写 `:model-value="edit[k] === '1'"` + `@update:model-value`，**不能 `v-model`**——store 里存的是字符串 `'1'/'0'`（与后端 `config_value TEXT` 一致），`v-model` 会把它改成布尔值，提交时后端 `getBool` 只认 `"1"/"true"/"yes"`，布尔 `true` 会被序列化成 `"true"` 侥幸能过、`false` 序列化成 `"false"` 也能过，但 `update_time` 里会留下一堆类型不一致的历史值。

## 7. 踩坑记录

1. **改站点名后登录页没变** —— 只改了 `MainLayout` 的品牌名，漏了 `LoginView` 的 `.auth-brand`。E2E 第 3 组就是为这条加的：未登录状态下 `goto('/login')` 后读 `.auth-brand`。

2. **`configMap()` 报 `TypeError: list is not iterable`** —— 未登录时 `GET /api/config` 返回的是 `{code:401,...}`，`Object.values()` 得到数字和字符串，`for...of` 直接炸。修法是在 `configMap()` 里先判断 `groups.code` 存在就抛出可读错误。E2E 脚本里出现这种「准备步骤没登录」的错，报错信息必须自己写清楚，否则排查全靠猜。

3. **E2E 各节之间必须对齐登录态** —— 第 3 节结尾为了验证「未登录也能看到站点名」主动 `logout()`，第 4 节开头就必须 `login()` 回来。第一次跑就是因为漏了这一步，报 `waitForSelector` 超时 30 秒，现象看起来像是页面坏了。

4. **注册页没有 `autocomplete` 属性** —— `page.fill('input[autocomplete="username"]')` 找不到元素。顺手给注册页的三个输入框补齐了 `autocomplete`（`username` / `new-password` / `new-password`），这本身也是该修的（浏览器密码管理器认不出来）。

5. **注册页断言「红字数量」会误判** —— 密码 8 位不合规 + 确认密码两次不一致是两个错误，光数 `.el-form-item__error` 的条数会把「确认密码不一致」当成「长度不合规」。改成断言提示文案里含 `12~32`。

6. **`page.reload()` 在错误的页面上执行** —— 第 8 节创建自定义项后直接 `reload()`，但此时停在工作台（第 6 节登录后的落点），`.cfg-row` 永远等不到。改成先 `goto('/admin/config')` 再断言。

7. **`el-switch` 的 `v-model` 会把字符串变成布尔** —— 见 4 节末尾。

8. **`String.prototype.replace(x, y, 1)` 在 PowerShell 里不存在** —— `$c.Replace($old, $new, 1)` 报「找不到 Replace 的重载」。要「只替换第一处」得自己用 `IndexOf` + `Substring` 拼。

## 8. 后续扩展注意

- 新增配置项时，**优先用 `POST /api/config` 建自定义项**，不要改代码加 `builtin`。内置项的判定标准是「代码里有兜底默认值」，加了内置项就必须同时改 `ConfigService` 的兜底常量与建表脚本，两边不一致会很难查。
- 前端新增密码输入的地方，一律走 `validatePassword(value, config.passwordRules)`；新增后端密码入口，一律走 `PasswordPolicy.check(pwd, configService.passwordRules())`，且 DTO 上只写 `@Size(max = 64)`。
- 站点 Logo（`site.logo`）目前只存字符串（URL 或 base64），前端还没渲染。要接的话加在 `MainLayout` 品牌的 `el-icon` 位置，注意 base64 图片长度别超 `config_value TEXT`。
- 公开配置接口目前没有任何限流。如果之后加了很多公开项，考虑给 `publicMap()` 的结果加 HTTP 缓存头（`Cache-Control: max-age=60`），配合 store 的 5 分钟 TTL 已经够用。
