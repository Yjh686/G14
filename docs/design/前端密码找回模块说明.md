# 前端密码找回模块说明

> 对应接口文档：`docs/api/密码找回接口.md`
> 后端实现：`backend/src/main/java/com/yjh/backend1/module/recovery/`
> 相关页面：登录页 / 找回密码页 / 个人资料页 / 用户管理页

---

## 1. 路由与入口

| 路径 | name | 权限 | 说明 |
|---|---|---|---|
| `/forgot-password` | `forgot-password` | `public: true` | 三步式找回页，**懒加载**（低频路径） |
| `/profile` | `profile` | 需登录 | 已有页面，新增「账号安全」卡片 |
| `/admin/users` | `admin-users` | `user:list` | 已有页面，操作列新增「更多 → 清除密保」 |

登录页入口的位置值得单独说：**「忘记密码？」放在密码框正下方**，不是放到底部「注册账号」旁边。理由很朴素——忘记密码的人此刻正在输密码，眼睛就在这一块，而「注册账号」那一行是给**没有**账号的人看的，两种人的视线根本不在同一个位置。

样式上给了 `margin: -8px 0 14px`，负上边距是为了抵消 `el-form-item` 自带的底部间距，否则它会飘在密码框和登录按钮中间，看起来像第三行表单。

## 3. 关键设计

### 3.1 三步式而不是一步填完

```
① 输入学号  →  ② 看见题面 + 答题 + 设新密码  →  ③ 成功
```

一步填完的意思是：一个表单里同时有「学号、密保问题 1、答案 1、密保问题 2、答案 2、新密码、确认密码」七行。问题在于**用户看到第一行时并不知道自己当年设的是什么题**，题面得等他填完学号、点了「下一步」才知道。硬塞进一个表单，只能先让他盲填两个答案，再在提交时报「题面不符」——而他连题目都没见过。

所以拆成两步：第一步只负责「换回题面」，第二步才让他在**看得见的问题**下答题。

第三步是 `el-result` 成功页而不是一个 toast，因为它要传达「其它设备上的登录状态已全部失效」这个信息——后端改了 `token_version`，他手机上的登录真的会掉。一句话飘过去，用户第二天会以为账号被盗了。

### 3.2 不发临时票据

第一步成功后只把题面存在前端 `questions` reactive 里，第二步把 `username` 原样再传一次。

没有「第一步换票据、第二步带票据」的设计，理由见接口文档 §6.4：题面本身是公开的（任何知道学号的人都能查到），票据能保护的信息量约等于零，却要多一份存储、过期时间和防重放。而重置成功与否只取决于答案对不对。

副作用是 `reset` 接口完全幂等，测试脚本也好写。

### 3.3 两个 API 对象刻意分开

```ts
export const recoveryPublicApi = { lookup, reset }   // 免登录
export const recoveryApi = { mine, myQuestions, setup }  // 需登录
```

如果合成一个对象，在登录页写 `recoveryApi.lookup()` 也「能跑」（TS 不报错），但注释会暗示这是需鉴权的接口；更糟的是有人反手在需登录的页面调 `recoveryPublicApi.reset()`，把一个「改密码」的免登录接口引进来，一旦参数拼错就是安全漏洞。

分开之后，导入哪一个本身就是意图声明。

### 3.4 密码提示跟着系统配置走

新密码的输入提示用的是 `{{ config.passwordRuleText }}`，校验用 `validatePassword(value, config.passwordRules)`，**没有写死「8~32 位」**。

这是 `docs/api/系统配置接口.md` §5 那条教训在前端的对应物：管理员把最小长度改成 12 之后，页面上如果还写着「8~32 位」，用户输 9 位会看到一个自相矛盾的报错。

`passwordRuleText` 是 `stores/config.ts` 里的 computed，会拼出「12~32 位，不含空格，且必须同时包含字母和数字」这样的完整句子。

### 3.5 密保对话框只回显题面，不回显答案

打开对话框时：

```ts
watch(visible, async (v) => {
  if (!v) return
  hasExisting.value = await recoveryApi.mine()
  if (hasExisting.value) {
    const q = await recoveryApi.myQuestions()
    form.question1 = q.question1   // 题面回显
    form.question2 = q.question2
    // 答案留空 —— 服务端只有 BCrypt 哈希，回显不出来
  }
})
```

已设置过的用户会看到 `el-alert type="warning"`：「原来的答案无法回显，保存后会完全覆盖之前的密保问题」。不写这句的话，用户会以为「我只要改问题 2，答案 1 会自动保留」——而实际保存是整个覆盖，答案 1 会变成空字符串校验失败，或者更糟：他把自己答得上来的答案改成了随手填的。

### 3.6 预设问题是可点击标签，不是下拉

四个预设：我的宿舍号是多少 / 我母亲的姓名是 / 我小学班主任姓什么 / 我的出生城市是。

做成 `el-tag` 点击填充，**填进输入框之后仍然可以改**。做成下拉就变成了限制——而「我小学班主任姓什么」这类题恰恰是自由输入才写得出来的（详见接口文档 §2.3）。

### 3.7 前后端同口径的答案归一化

前端校验「两答不能相同」时用的是：

```ts
const norm = (s: string) => s.trim().toLowerCase()
```

与后端 `normalizeAnswer` 的前半段一致（后端还多做了全角转半角）。如果前端只 `trim()` 不转小写，用户填「王秀兰」和「王秀兰 」会被前端放行、被后端拒绝，报错行还指不到具体哪一项。

### 3.8 管理员的「更多」下拉

用户管理页操作列原本是四个链式按钮：编辑 / 重置密码 / 禁用 / 删除。加上「清除密保」就是五个——在 1440px 下会挤成两行，操作列的 `fixed="right"` 又会把第二行挡住一半。

改成三个直接按钮 + `el-dropdown`：

```
[编辑] [重置密码] [禁用] [更多 ▾]
                          ├─ 清除密保
                          └─ 删除账号
```

收进下拉的两个是「一个月也用不到一次」的操作。删除还加了 `divided` 分隔线，因为它不可撤销。

## 4. 页面结构与状态

### 4.1 `ForgotPasswordView`

```
auth-wrapper
└── auth-card
    ├── el-steps (3 步：核对账号 / 验证密保 / 完成)
    ├── step === 1
    │   ├── el-form-item 学号/工号
    │   └── [下一步]  ← 只 validateField('username')
    ├── step === 2
    │   ├── el-alert  显示两个题面（只读）
    │   ├── el-form-item 答案 1 / 答案 2
    │   ├── el-form-item 新密码 / 确认新密码
    │   ├── .field-tip 密码规则（来自配置）
    │   ├── [换个账号] [重置密码]
    │   └── .foot-hint 连续答错会被临时锁定
    └── step === 3
        └── el-result icon=success
            ├── 密码已重置
            ├── 其它设备上的登录状态已全部失效
            └── [去登录]
```

`step` 是 `ref<1|2|3>`。切回第一步时清空答案与密码——不复用上一次的输入，因为那是另一个账号的答案。

### 4.2 `RecoverySetupDialog`

```
el-dialog  title = hasExisting ? '修改密保问题' : '设置密保问题'
├── el-alert type=info   答案会加密封存，任何人都看不到原文
├── 问题 1 [input maxlength=120]  + 四个预设 tag
├── 答案 1 [input type=password maxlength=200]
├── 问题 2 [input maxlength=120]  + 四个预设 tag
├── 答案 2 [input type=password maxlength=200]
└── [取消] [保存]
```

答案框用 `type="password"`：不是为了防肩窥（旁边没人），而是为了让人**意识到这是敏感信息**，别顺手往班级群里复制。

### 4.3 `ProfileView` 的「账号安全」卡片

单独一张 `el-card`，不塞进个人资料表单。因为两者语义不同：个人资料是「别人能看到的我」，密保是「账号能不能找回来」。混在一起，用户会以为改资料时顺便改了密保。

卡片右侧用一个 `el-tag`（`success` 已设置 / `warning` 未设置）+ 一个按钮（「修改密保」/「去设置」）。`loadRecovery()` 失败时一律按「未设置」处理——接口不可用时最合理的默认是让用户去设置，而不是显示一个可能过期的「已设置」。

## 6. 测试

### 6.1 浏览器验证脚本

| 脚本 | 断言 | 覆盖 |
|---|---|---|
| `scripts/e2e-recovery.mjs` | 44 | 设置密保（预设标签、两问相同被拦）→ 未登录走「忘记密码」两步式（换题面 → 答题 + 新密码）→ 答错两次剩余次数 4→3 确实递减 → 新密码可登录 → 管理员「更多→清除密保」→ 确认框在视口中心且有遮罩（回归 17b7275）→ 操作列按钮纵向对齐（回归 9c698a5）→ 结束时自动复原演示账号 |

这一条已并入 `package.json` 的 `e2e:all`（`npm run e2e:recovery`）；接口层的长期防线在 `deploy/test/smoke_recovery.ps1`（55 条，可重复执行）。

写这个脚本踩到的三个坑，都写进了 `frontend/AGENTS.md`：

1. **确认框的定位在 `.el-overlay-message-box` 上**。`.el-message-box` 本身是 `position: relative` / `z-index: auto`，第一版断言读它，报「position 不是 fixed」判失败；实测几何中心其实是 (720,480)、遮罩铺满 1440×1000，渲染一直是好的——是断言选错了元素。现在改为量 overlay 的 `position`/`zIndex`/尺寸 + box 的几何中心。
2. **改密码的 E2E 必须在 `finally` 里复原，且开头先自检**。第一次跑崩在第 6 节，学生密码停在测试值，于是下一轮直接卡在 `login()` 超时，报错位置与真正原因（上一轮没复原）毫无关系。现在开头 `tryLogin()` 探测、不可用就先复原，`finally` 再复原一次。
3. **搜索框没有 watch**。`fill()` 之后要 `press('Enter')`，否则列表不刷新，断言「搜索不到目标用户行」。
4. **`Failed to load resource: 401/400` 不算控制台报错**。本脚本故意用错误密码、故意答错密保，不过滤这些就等于要求测试别测失败路径。

### 6.2 手工验证边界

- **手机端**：找回页在 390px 下表单完整、`el-steps` 会折成两行但不溢出；密保对话框走全局 `.el-dialog { width: calc(100vw - 24px) }` 规则。
- **改密保后旧答案失效**：改完之后用旧答案 `reset` 应当失败。这条脚本没覆盖，因为要占用一次失败计数。

## 7. 踩坑记录

1. **`el-message-box` 掉到页面底部**（历史缺陷 17b7275）。按需引入 Element Plus 后，`ElMessageBox` 是 `import` 进来的，`unplugin-vue-components` 不管它，样式缺失 → 没有 `position: fixed` 与遮罩，退化成块级元素排在 `<body>` 末尾。已在 `main.ts` 显式引 `message-box/style/css`。**新增任何编程式 API 都要记得引样式**。
2. **表格操作列的 `el-dropdown` 与 `el-button` 不对齐**（历史缺陷 9c698a5）。`el-dropdown` 默认 `vertical-align: top`，按钮是 `middle`，差 4px；且没有 12px 间距。已在 `global.css` 加通用规则。
3. **`confirmBox.locator('button:has-text("清除")')` 会匹配到「清除密保」以外的按钮**。写成 `button:has-text("清除")` 在对话框里是安全的（只有一个主按钮），但若之后文案变成「确定清除」，就得改成精确匹配。
4. **`.el-message` 是全局单例容器**。连续两次失败后读 `.el-message` 的 `innerText`，可能读到上一条还在淡出的提示；脚本里用 `waitForTimeout(1400)` 等它稳定。
5. **`recoveryApi.mine()` 返回 `true/false` 而不是对象**。拦截器把 `body.data` 直接返回，所以 `await recoveryApi.mine()` 拿到的就是布尔值，别写成 `.data`。
6. **密保对话框的 `watch(visible)` 要判断 `if (!v) return`**。否则关闭对话框时（`v` 变 `false`）也会重新拉一次接口，白花两次请求。
