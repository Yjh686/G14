# 前端问卷模块说明

本文说明前端问卷相关页面（列表、编辑器、预览、填写、答卷管理）的实现方式、与后端接口的对应关系，以及开发时踩过的坑。认证与后台部分见 [前端架构说明](./前端架构说明.md)。

## 1. 页面与路由

| 路由 | 名称 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/surveys` | `surveys` | `survey:list:self` 或 `survey:list:all` | 我的问卷列表 |
| `/surveys/new` | `survey-create` | `survey:create` | 新建问卷（复用编辑器组件） |
| `/surveys/:id/edit` | `survey-edit` | `survey:update:self` 或 `survey:update:all` | 编辑问卷 |
| `/surveys/:id/preview` | `survey-preview` | `survey:preview` | 预览（只读） |
| `/surveys/:id/answers` | `survey-answers` | `answer:read:survey:self` 或 `answer:read:survey:all` | 答卷管理 |
| `/surveys/answers/:sheetId` | `answer-detail` | 同上 | 单份答卷详情 |
| `/fill` | `survey-hall` | `survey:fill` | 问卷大厅 + 分享码入口 |
| `/fill/:key` | `survey-fill` | `survey:fill` | 填写页，`:key` 是问卷 id 或分享码 |

## 3. 四个关键设计

### 3.1 填写页与预览页共用 `QuestionRenderer`

填写页与预览页都要按题型渲染题目。复制两份的后果是样式与交互迟早漂移（比如单选按钮间距、字数限制提示位置），所以抽成一个组件：

```vue
<QuestionRenderer
  :model-value="answerFor(q.id)"
  :question="q"
  :index="qi"
  :invalid="invalidIds.includes(q.id)"
  readonly           <!-- 预览页传这个 -->
  @update:model-value="setAnswer(q.id, v)"
/>
```

- 作答状态统一用 `AnswerInput`（`optionValues` / `textValue` / `numberValue`），提交时直接把这个数组发给后端，不做二次转换。
- 单选题的 `el-radio-group` 只接受单值，组件内部在 `number | null` 与 `optionValues: [id]` 之间做了转换；多选直接绑数组。
- `readonly` 只是把 `el-radio` / `el-input` / `el-rate` 置为 disabled，不额外隐藏任何东西 —— 预览要看到填写者真实会看到的样子。

### 3.2 编辑器整卷提交，靠后端差量

编辑器维护本地 `questions: QuestionSaveRequest[]`，保存时一次 `PUT /surveys/{id}/questions` 提交整卷，而不是逐题调接口。原因：拖拽排序会一次改动多题，逐题调用既慢也无法保证顺序一致；整卷提交在后端天然是原子的。

- 有 `id` 的题目 → 更新；无 `id` → 新增；库里有但本地没有 → 删除（连带选项）。
- 选项一律「删旧建新」，所以选项 id 每次保存都会变，前端不依赖选项 id 做键。
- 新建流程是「先 `POST /surveys` 拿到 id，再 `PUT /questions`，最后 `router.replace` 到 `/surveys/{id}/edit`」，否则刷新会丢掉未保存内容且无法保存题目。

### 3.3 发布后整页降级为只读

`structureEditable = status === 'DRAFT'`。发布后：

- 「添加题目」按钮不渲染；
- 题型下拉、题干、选项、字数/评分上限、匿名与限填开关、开始时间全部 `disabled`；
- 只有标题、简介、截止时间还能改（后端 `SurveyService.update` 同样只放行这三个字段，改了别的会 400）。

这样用户不会先改半天再被后端拒绝。

### 3.4 填写页 `:key` 同时接受 id 与分享码

```
/fill/Q3PTC5RC   ← 分享链接，学生用
/fill/1          ← 大厅跳转，理论上也可以
```

用 `:key` 一个参数承载两种值，省掉一套几乎重复的视图。判断逻辑是 `/^\d+$/` 为 id，否则当分享码（转大写后查）。

**重要**：大厅跳转实际用的是 `shareCode` 而不是 `id`。因为 `/surveys/{id}` 需要 `survey:update:self|all` 或 `survey:preview` 权限，学生没有这些权限会 403；而 `/surveys/share/{code}` 只要求 `survey:fill`，才是填写者的入口。

```ts
function open(row: HallSurveyVO) {
  const key = row.shareCode ?? String(row.id)
  router.push({ name: 'survey-fill', params: { key } })
}
```

## 4. 填写页的状态机

进入页面后先取卷，再取 `fill-state`，然后按四种情况渲染：

| 条件 | 渲染 |
| --- | --- |
| `fillable === true` | 答题表单 |
| `submitted === true && limitOnce === 1` | 「你已提交过该问卷」+ 提交时间 |
| `fillable === false`（其他原因） | 「问卷尚未开始 / 已暂停回收 / 已结束 / 已过截止时间」 |
| 提交成功后 | 回执页（编号 + 时间 + 匿名提示） |

`reason` 是后端返回的机器码（`NOT_STARTED` / `PAUSED` / `CLOSED` / `EXPIRED` / `ALREADY_SUBMITTED`），前端用 `fillReasonText()` 翻译，不解析中文文案。

### 草稿自动保存

- 5 秒防抖：作答变化后 `setTimeout` 重置，只有停手 5 秒才发请求（FR-FILL-04）。
- `onBeforeUnmount` 里补一次保存 —— 用户可能在防抖触发前就关掉页面。
- 草稿保存失败**不弹错误**，只在控制台留痕：草稿是尽力而为，弹窗打断作答反而糟糕。
- 只提交有内容的题：三个字段全空的题不会进 `answers` 数组。
- 断点续答：`fill-state` 返回的 `draftAnswers` 摊成 `Record<questionId, AnswerInput>`，直接作为初始值。

### 本地校验 vs 后端校验

本地校验只负责**定位并高亮**第一道未填的必答题（`invalidIds` + 红底），文案与后端风格一致但不完全等同；真正判定必答、选项归属、字数、评分范围的是后端。前端预检的收益是省一次往返和更好的定位体验，不是安全边界。

## 5. 匿名在两端的表现

匿名不是「前端隐藏」，而是后端 DTO 裁剪后前端自然没有可显示的东西：

| 页面 | 匿名时的表现 | 依据 |
| --- | --- | --- |
| 答卷列表 | 填写人列显示「匿名」，学号列显示 `-` | 接口返回 `userId`/`fillerName`/`fillerUsername` 均为 `null` |
| 答卷详情 | 填写人显示「匿名（问卷设置为匿名）」 | 同上 |
| 我的填写记录 | 操作列显示「匿名，不回显」，**不渲染「查看作答」按钮** | `contentVisible === false` |
| 我的答卷详情 | 直接进入也不会看到内容 | `items` 与 `questions` 都是 `null` |
| 提交回执 | 提示「该问卷为匿名问卷，提交后不再显示作答内容」 | 按 `anonymous` 判断 |

前端不给入口（而不是点进去看到空页面），是因为空白页会让用户以为功能坏了。

## 8. 踩过的坑

1. **`noUncheckedIndexedAccess` 已开启**（`tsconfig.app.json`）。所有 `arr[i]` 的类型都是 `T | undefined`，取完必须判空或改用 `.find()` + 判空。编辑器里 `questions.value[i]`、填写页 `questions.value[idx]` 都踩过。
2. **`v-model` 不能直接绑 `answers[q.id]`**。`answers` 是 `Record<number, AnswerInput>`，索引可能为 `undefined`，`v-model` 要求的类型是确定的 `AnswerInput`。解法是 `answerFor(id)` 兜底返回空对象，再用 `:model-value` + `@update:model-value` 显式赋值。
3. **填空（TEXT）渲染成单行 `input`，多行文本（TEXTAREA）才是 `textarea`**。E2E 里按 `textarea` 找填空题会超时，选择器要写 `input[placeholder="请输入"]`。
4. **路由变化早于详情接口返回**。复制问卷后 `waitForURL` 通过时输入框还是空的，断言标题要等 `input.value.length > 0`（`page.waitForFunction`）。
5. **`el-switch` 的布尔值要传 1/0 而不是 true/false**。后端 `anonymous` / `limitOnce` 是 `Integer`，传布尔会 500：`Cannot deserialize value of type java.lang.Integer from Boolean value`。组件上用 `:active-value="1"` `:inactive-value="0"`。
6. **`el-radio-group` / `el-checkbox-group` 不接受 `null`**。单选初值用 `optionValues: []`，`singleValue` 的 getter 取 `optionValues?.[0]`，setter 写回 `[v]` 或 `[]`。
7. **表格里不要在 `template #default` 里写多行箭头函数体**。审批/更多菜单那类 `@command` 回调建议抽成具名方法，模板内联多行 `if` 会让 `vue-tsc` 的模板类型推断失效。

## 9. 后续扩展注意

- 统计与图表接口（`/api/surveys/{id}/stat`）尚未开发，`SurveyAnswersView` 的「导出」按钮目前只弹「将在下一个模块实现」的提示。
- 列表页的主 chunk 已接近 1.3 MB（Element Plus 全量引入）。若要优化首屏，先把 `element-plus` 改成按需引入，再对 `SurveyEditView`（12.7 kB）与 `UserListView`（12.3 kB）做路由拆分 —— 路由已全是 `() => import(...)`，拆分成本很低。
- 若以后要支持「指定填答名单」，`AnswerSummaryVO.expectedCount`（当前是启用学生账号数）与 `completionRate` 的分母口径需要一起改，前端统计卡片文案也要同步。
