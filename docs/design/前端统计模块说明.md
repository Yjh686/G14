# 前端统计模块说明

> 对应后端：`module/stat/`（FR-STAT）+ `module/export/`（FR-EXP）
> 接口文档：`docs/api/统计与导出接口.md`
> 验证：`npm run e2e:stat`（34 条）、`npx vitest run`（chart.spec.ts 8 例）

## 1. 页面与路由

| 路由 | name | 组件 | 权限 | 入口 |
|---|---|---|---|---|
| `/surveys/:id/stats` | `survey-stats` | `SurveyStatsView.vue` | `stat:read:self` \| `stat:read:all` | 问卷列表「更多 → 统计分析」、答卷管理页「统计分析」按钮 |

统计不单独挂一级菜单：统计总是「某一份问卷的统计」，脱离问卷的统计入口没有意义，挂在一级菜单上只会让用户点进去再选问卷。

## 3. 五个关键设计

### 3.1 ECharts 按需注册，不 `import * as echarts`

```ts
import * as echarts from 'echarts/core'
import { BarChart, PieChart } from 'echarts/charts'
import { GridComponent, LegendComponent, TitleComponent, TooltipComponent } from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'
echarts.use([...])
```

全量 `import * as echarts from 'echarts'` 会让统计页 chunk 从 510KB 涨到 1MB 以上。按需注册后 `SurveyStatsView-*.js` 是 510KB（gzip 172KB），而且因为路由懒加载，**只有打开统计页的人才下载它**——登录页和填写页完全不受影响。

没有注册的图表类型（雷达、词云等）即使 option 里写了也画不出来，这是有意的：需要新图表时应该显式加一行 `echarts.use`，而不是靠全量引入蒙对。

### 3.2 一次拉整卷统计，本地切题

```ts
stats.value = await statApi.survey(surveyId)     // 一次
activeId.value = questions.value[0].questionId   // 切题只改这个
```

不采用「点一题拉一次」的理由：

- 课级问卷最多 100 题、单份统计 JSON 通常几十 KB，一次拉完的等待是几百毫秒；
- 「点一题拉一次」把这个等待分摊到每次点击，交互上更难受；
- 切换题目时零延迟，且前后题的数字来自同一时刻，不会出现「第 1 题说 5 份、第 2 题说 6 份」的错觉。

单题接口 `/stats/questions/{id}` 仍然保留并测过（`smoke_stat.ps1` 第 9 组），将来数据量真的大了可以切过去，前端改动只是在 `activeId` 的 watch 里加一次请求。

### 3.3 多选不画饼图

`SurveyStatsView.vue` 里饼图的条件是 `active.questionType === 'SINGLE'`，同时多选题上方固定显示一条 `el-alert`：

> 多选题占比之和会超过 100% —— 分母是「该题有效作答人数」，不是选项总数，本页不画饼图也是这个原因。

这条提示不是装饰。没有它，用户看到「80% + 60% + 40% + 40%」会直接认为系统算错了，然后来问「为什么加起来 220%」。解释一次的成本远低于写一行 `v-if`。

### 3.4 统计页不出现填写人

`QuestionStatsVO.text.answers[]` 里只有 `{ text, submitTime }`，后端 DTO 就没给 `userId / fillerName`。前端也没有任何「我想看是谁写的」的入口。

这是匿名约束的一部分：**匿名问卷的身份裁剪在后端出口做，统计页只是没有那两列**。即使将来有人在前端加一个「显示填写人」按钮，也拿不到数据。

实名的作答明细去「答卷管理 → 查看」里看，那里有权限控制（`answer:read:survey:*`）。

### 3.5 词频用条形图不用词云

词云需要额外注册 `echarts-wordcloud` 插件，而中文字号映射后的可读性很差（「作业」两个字和一个单字在同一个气泡里，字号差一倍看着像排版错误）。横向条形图能直接读出次数，也更好解释「为什么这个词算高频」。

页脚写明了算法：「两字滑窗切分，只保留出现 ≥ 2 次的词，已过滤常见虚词，用于快速看倾向，不替代人工阅读」。这句话是为了防止用户把词频当结论引用。

## 4. 图表容器 BaseChart

```vue
<BaseChart :option="barOption(active.options, active.answeredCount)" :empty="activeEmpty" height="300px" />
```

三个 prop：

| prop | 说明 |
|---|---|
| `option` | 由 `utils/chart.ts` 构造，深度 watch 变化即 `setOption(option, true)` |
| `empty` | `true` 时清空画布并显示 `el-empty`，**不渲染 0 值的空图表** |
| `emptyText` | 占位文案，默认「暂无数据」 |

两个实现细节：

- **用 `shallowRef` 存 echarts 实例**。实例内部有大量循环引用，`ref` 会深度代理它，`dispose()` 时可能报错。
- **用 `ResizeObserver` 而不是 `window.resize`**。侧边栏折叠时容器宽度变了但窗口没变，只听 `window.resize` 图表会横向压扁。

`setOption(option, true)` 的第二个参数 `notMerge=true` 是必须的：切换题型时如果不合并，上一题的 series 会残留，出现「单选题下面挂着评分柱」的诡异图。

## 5. 导出为什么不能用 `get<T>`

`src/api/http.ts` 的响应拦截器有这段逻辑：

```ts
const body = response.data as ApiResult
// 文件下载等非 JSON 响应直接透传
if (body == null || typeof body !== 'object' || !('code' in body)) {
  return response as unknown as typeof response
}
```

导出接口返回二进制，`body` 是 Blob，没有 `code` 字段，于是走「原样透传」分支——**拿到的是完整的 `AxiosResponse`，不是 `data`**。所以 `exportAnswers()` 必须：

```ts
const res = await http.get(url, { responseType: 'blob' })
const axiosRes = res as unknown as AxiosResponse<Blob>
const blob = axiosRes.data
const name = axiosRes.headers['content-disposition']  // ← 文件名在这里
```

文件名必须从 `Content-Disposition` 读，不能前端拼：后端做过非法字符替换和 60 字截断，而且时间戳用的是后端时钟。优先解析 RFC 5987 的 `filename*=UTF-8''...`（`decodeURIComponent`），否则中文名会退化成 `export.xlsx`。

出错时后端返回的是 JSON，`blob.type` 会是 `application/json`，此时要把里面的中文 `msg` 读出来抛给用户——直接显示「导出失败（500）」等于让用户猜。

## 6. 空数据的显示

| 场景 | 表现 |
|---|---|
| 整卷 0 份有效答卷 | 顶部 4 个卡片显示 0，下方一条 `el-alert`「还没有有效答卷」，图表区全部是 `el-empty` |
| 单题 0 人作答（非必答题被全员跳过） | 该题图表显示占位，但题目导航里仍可点进去看到「0 人作答」 |
| 问卷没有题目 | 整页 `el-empty`「这份问卷还没有题目」 |
| 文本题无高频词（都是短句） | 不显示词频区域，但作答列表照常显示 |

`activeEmpty` 只看 `answeredCount === 0`，不看 `validSheetCount`：一份答卷都没收到时两个都是 0，但有答卷却被全员跳过时后者不为 0，此时应该显示「没人答这题」而不是「还没有答卷」。

### E2E（`scripts/e2e-stat.mjs`，34 条）

造数据走接口（`page.evaluate` + `fetch`，带当前登录态）而不是走界面：5 种题型共 10 多个字段，用界面点一遍既慢又和 `e2e-survey.mjs` 重复。脚本只验证「统计页本身」，最后统一删除自己造的问卷。

覆盖：概览数字 → 5 题导航 → 单选双图与占比 → 多选单图与提示 → 文本高频词与列表 → 评分平均分 → Excel 下载（文件名含标题）→ 学生被拦到 403 → 无控制台报错。

## 8. 踩坑

1. **`import type { CallbackDataParams } from 'echarts/types/dist/shared'`** —— 给 `label.formatter` 标类型时必须用它。自己写 `(p: { value: number }) => string` 会因为 `params.value` 可能是 `string | number | Date | null` 而 TS 报错，而这个错会指向整个 series 的类型不兼容，看起来像是 option 结构写错了。
2. **`vite build` 的 chunk 体积警告仍然存在**（主 chunk 1.29MB）。这是 Element Plus 全量引入导致的，统计页的 echarts 是独立 chunk，不影响登录页首屏。要彻底解决得做 Element Plus 按需引入，属于全局优化，不在本模块范围。
3. **dev server 会被上一条 pwsh 命令结束时带走**。跑 E2E 前必须在同一条命令里先 `Start-Process node ... vite.js` 再 `node scripts\e2e-stat.mjs`。
4. **造数据时选项 id 不能凭下标猜**。必须先取 `GET /surveys/{id}` 拿真实 `questions[].options[].id`，再拼提交体；直接写 `optionId: 152` 会在换库、换机器后失效。
5. **5 份答卷常常落在同一秒**，文本作答按时间倒序排序不稳定。E2E 别断言「第一条是什么」，改成断言「全部作答里包含某个词」。
6. **`el-radio-group` 的占比进度条**用 `Math.round(ratio * 1000) / 10` 转百分比，不能直接 `ratio * 100`：`0.4 * 100 = 40.00000000000001`，`el-progress` 会报「percentage 必须是 0~100」。
