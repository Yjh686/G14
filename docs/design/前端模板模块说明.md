> 对应后端：`module/template/`（接口文档见 `docs/api/模板中心接口.md`）

## 1. 页面与路由

| 路由 | name | 权限 | 说明 |
|---|---|---|---|
| `/templates` | `templates` | `template:browse` / `share` / `audit` 任一 | 模板中心（浏览） |
| `/templates/:id` | `template-detail` | 同上 | 模板详情（含结构） |
| `/my-templates` | `my-templates` | `template:share` | 我共享的模板 |
| `/admin/template-audit` | `admin-template-audit` | `template:audit` | 审核队列 |

侧边栏挂了三项：模板中心（三个视角任一权限都显示）、我共享的模板（`template:share`）、模板审核（`template:audit`，和用户管理一组排在最后）。详情页 `hidden: true`，不进菜单。

**学生只看到「模板中心」一个入口**——他们有 `template:browse` 和 `template:rate`，没有 share/offline/use/audit。

## 3. 六个关键设计

### 3.1 模板详情不能复用 `QuestionRenderer`

`QuestionRenderer` 的 `v-model` 绑的是 `AnswerInput.optionValues`——**选项 id 数组**。而模板里的选项是**纯文本数组**（`string[]`），没有 id。

所以模板详情和审核抽屉各写了一份只读题目列表（`.q-item` + `<ul><li>`）。看起来重复，但强行复用要改 `QuestionRenderer` 的契约，让它同时吃 id 数组和字符串数组，反而更容易出错。

**判断标准**：`QuestionRenderer` 服务于「作答」，模板结构服务于「查看与复制」，两件事。

### 3.2 评分控件不能开 `allow-half`

后端 `score` 是 `TINYINT`，1~5 的整数。`el-rate` 加了 `allow-half` 之后用户能点出 4.5，请求会被 400 拒掉。

所以：

- **交互态**（学生评分）：`allow-half` 关闭
- **只读态**（显示 `ratingAvg`）：`allow-half` 打开，这样 4.5 分能显示半颗星

还有一个坑：`el-rate` 再点一次已选中的星会**归零**，`@change` 收到 `0`。后端不接受 0，所以 `rate()` 第一行就是 `if (!score) return`，静默忽略。

### 3.3 「暂无评分」不等于「0 分」

后端 `ratingAvg` 在无人评分时是 `null`，不是 `0`。前端统一走 `ratingText(avg, count)`：

| 输入 | 输出 |
|---|---|
| `ratingAvg = null, count = 0` | `暂无评分` |
| `ratingAvg = 0, count = 0` | `暂无评分` |
| `ratingAvg = 4.0, count = 2` | `4.0 分（2 人）` |

如果直接 `ratingAvg?.toFixed(1) ?? '0.0'`，新模板会显示成「0.0 分」——比「暂无评分」伤人得多。

### 3.4 使用模板后必须立刻跳走

`useTemplate()` 成功后的动作是 `router.push({ name: 'survey-edit', params: { id: survey.id } })`，不是留原地弹个 toast。

留原地会怎样：用户点了「使用模板」，看到「已创建草稿」的提示，然后**不知道该去哪**——模板卡片没有任何变化（模板本身没变，只是 `useCount + 1`），用户会怀疑没成功，再点一次，就有了两份草稿。

跳到编辑器是唯一能自然衔接下一步（改名 → 发布）的选择。

### 3.5 审核队列的默认视图是「待审核」

`query.status` 初始值 `'PENDING'`，不是空。管理员打开审核页看到的第一屏就是**要处理的活**，而不是一堆已经审完的记录。`clearable` 让他想看全部时能清掉。

筛选区的提示 tag「当前显示待审核，共 N 个」是给不熟悉这个页面的人看的——否则「为什么列表里只有 3 个模板，明明有很多」这种疑问每次都要重新解释。

### 3.6 共享对话框不需要用户理解「快照」

用户填的是：选一份自己的问卷 → 模板名（自动带出）→ 说明 → 分类。题目结构完全不出现在表单里。

技术上的「快照」对用户不可见，但对话框顶部有一条 `el-alert`：

> 共享的是当前问卷的一份快照，之后你再改问卷不会影响已共享的模板。

这句话不是给开发看的，是给老师看的——不然他共享完可能会回去改原问卷，期待模板跟着变。

## 4. 各页面的状态与交互

### 4.1 模板中心（`TemplateCenterView`）

按钮显隐按权限和状态：

| 按钮 | 显示条件 |
|---|---|
| 「我共享的模板」 | `template:share` |
| 「使用模板」 | `template:use` |
| 可交互 `el-rate` | `template:rate` |
| 只读 `el-rate` | 其他所有人（用 `ratingAvg`） |

卡片上不显示 `status`——这个页面只有 `APPROVED` 的内容，显示状态 tag 是噪音。

### 4.2 我共享的模板（`MyTemplatesView`）

操作按钮完全由 `status` 决定：

| 状态 | 可用操作 |
|---|---|
| `PENDING` | 查看 |
| `APPROVED` | 查看、下架 |
| `REJECTED` | 查看、重新提交、删除 |
| `OFFLINE` | 查看、删除 |

审核意见列在 `REJECTED` 时用红色显示——那是用户需要处理的信息，不是装饰。

### 4.3 审核队列（`TemplateAuditView`）

- 内容预览用 `el-drawer`（560px）而不是跳新页：审核是一件「看一眼就决定」的事，跳页会丢失队列位置
- 抽屉关掉后表格还在原位置，可以直接审下一条
- 驳回对话框的引导文案会显示模板名，并说明「共享者会看到下面这句话」——让审核员写具体的、能指导修改的意见，而不是「不合适」

### 4.4 模板详情（`TemplateDetailView`）

`detail()` 对未过审模板返回 404（非本人），所以页面的空态是「模板不存在或未通过审核」，不是「加载失败」。

## 7. 踩坑

1. **`el-rate` 再点同一颗星会归零**，`@change` 传 `0`，后端 400。所有评分入口都要 `if (!score) return`。
2. **模板选项是 `string[]`**，不是 `{id, content}`。写 `.options[0].content` 会得到 `undefined`。
3. **编辑器里的题干和选项是 `<input>`**，`innerText` 取不到，E2E 断言必须用 `inputValue()` / `evaluateAll(e => e.value)`。第一次跑 e2e 就踩了：`.question` 选择器在编辑器里根本不存在（编辑器的类名是 `.question-item`，`.question` 是 `QuestionRenderer` 的）。
4. **`ratingAvg` 为 `null` 时不能 `.toFixed()`**，会抛异常导致整个卡片白屏。
5. **审核抽屉和详情页都用 `el-tag` 显示 `questionType` 原值**（`SINGLE` 而不是「单选题」）——只有审核员和共享者看，用原值是给开发视角的便利。想改中文的话用 `questionTypeLabel()`。
6. **`el-switch` 绑的是 `Integer(1/0)`**：`shareForm.anonymousDefault` 通过 `:model-value="... === 1"` + `@update:model-value="v => (x = v ? 1 : 0)"` 转换，不能直接 `v-model` 一个 boolean。

## 8. 后续扩展注意

- 如果将来要支持「模板包含评分量表/矩阵题」，`TemplateQuestionVO` 要跟 `QuestionVO` 一起改，且 `structure_json` 是历史数据，读的时候必须有默认值兜底（`readStructure()` 解析失败就给空结构，不让详情页 500）。
- 模板如果要做「官方推荐」标记，加在 `survey_template` 上而不是 `template_rating`——那不是用户评分。
- 现在审核是一次性通过/驳回，没有「审核意见多轮对话」。如果要做，`survey_template` 需要一张 `template_audit_log` 表存历史，`audit_remark` 只保留最后一次。
